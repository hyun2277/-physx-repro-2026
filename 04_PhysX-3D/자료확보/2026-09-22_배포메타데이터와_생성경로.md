# 2026-09-22 PhysXNet 배포 메타데이터와 입력·카메라 생성 경로

## 조사 범위

고정 upstream `PhysX-3D` 소스(커밋 `4f54e750a309fe9cd9f20816916ecc0e8a9ae594`), 해당 README/전처리 스크립트, 공식 Hugging Face revision `ca1f6d3f5cfb5c39dc183251a3a2999dcb42e093`의 공개 파일 목록, 로컬 `PhysXNet.zip` 중앙 목록만 읽었다. ZIP은 추출하지 않았고, 새 다운로드·모델/GPU 실행·전체 평가·원본 코드 수정은 하지 않았다.

| CSV, TXT, YAML/YML, NPY/NPZ | 0 | archive metadata/split 파일 없음 |
| `transforms.json`, `metadata*`, `instance*`, `index*`, `split*`, `render*`, `texture*`, ShapeNet/PartNet 경로 | 0 | 파생 메타데이터/texture 없음 |
| `camera` 문자열 | 1 | `version_1/partseg/11728/imgs/2_camera.png`라는 part PNG 파일명일 뿐 camera metadata가 아님 |

후보 `7271`과 `29354`의 member 집합도 각각 JSON 1개·OBJ 6개·PNG 6개뿐이다. ZIP 파일 자체의 공개 revision metadata는 `PhysXNet.zip` 16,306,354,206 bytes, SHA256 `a4970a3936e8a1fc823d17b64d23b167d73997a13686011bc46f7b98774a7e75`를 제시한다.

## 2. 공식 공개 배포와 파생 파일 구분

공식 Hugging Face API 파일 목록에는 `.gitattributes`, `README.md`, `PhysXNet.zip`과 `PhysXNet-XL_*` zip/분할 파일들만 있고 `metadata.csv`, `renders_cond`, `transforms.json`, 표본별 texture mapping은 없다. 따라서 아래 구분을 유지한다.

| 자료 | 공식 배포 여부 | 근거와 생성 경로 |
|---|---|---|
| PhysXNet.zip | 배포됨 | README의 `huggingface-cli download ... PhysXNet.zip` |
| `val_test_list.npy` | 코드 저장소 파일 | PhysX-3D Git 저장소; README는 앞/뒤 1000개 split이라고 설명. PhysXNet.zip member가 아님 |
| `metadata.csv` | 파생 | `gen_csv.py:11–26`이 `phy_dataset/*/model_tex.obj` 목록으로 생성하고, `build_metadata.py:86–103`이 상태 열을 추가 |
| `renders/<instance>/*`, `renders_cond/<instance>/*` | 파생 | `render.py`/`render_cond.py`가 `metadata.csv.local_path`를 Blender에 넘겨 생성 |
| `transforms.json` | 파생 | Blender `render.py:482–497`이 frame 파일명/FOV/행렬을 저장 |
| texture mapping | 외부 원본+파생 | README는 PartNet에 texture가 없어 ShapeNetCore를 별도 `dataset_toolkits/shapenet`에 두라고 한다. `retrieval_texture_example.py`가 `finalindex.json` mapping을 사용한다 |

README는 원시 ZIP을 `physxnet`으로 푼 뒤 `precess.sh`에서 `merge_property.py`, `gen_csv.py`, texture retrieval, `render.py`, `render_cond.py` 순으로 파생 자료를 만들도록 한다. 이 산출물들은 공개 ZIP 안에 들어 있지 않다.

## 3. render_cond 재현성

`render_cond.py:26–45`는 다음을 사용한다.

- 입력: `metadata.csv`에서 `local_path`가 존재하는 행. `--instances`를 주면 `sha256` 열과 일치하는 instance만 선택한다(`89–107행`).
- instance ID: `gen_csv.py`가 `phy_dataset` 디렉터리 이름에 `_`를 붙인 `sha256` 열을 만든다. 이는 cryptographic hash라기보다 처리용 식별자다.
- 기본 산출량: 24 views, 1024 해상도(`74–75`, `47–54행`), `renders_cond/<sha256>/transforms.json`.
- 랜덤성: `np.random.rand()`로 Hammersley offset을 만들고(`32행`), `np.random.uniform(..., (1000000,))`에서 각 view의 radius/FOV를 뽑는다(`42–45행`). 스크립트에 seed 설정이 없다.
- Blender가 `yaw`, `pitch`, `radius`, `fov`를 사용하고 `transforms.json`에 `camera_angle_x`와 `transform_matrix`를 기록한다(`blender_script/render.py:455–497`).

따라서 같은 프로세스의 RNG 상태/offset/반복 추출값을 별도로 보존하지 않으면 bitwise 동일한 조건 이미지를 재생성할 수 없다. seed를 외부에서 고정해도 Blender·NumPy 버전과 입력 mesh/texture가 같다는 추가 조건이 필요하다. 더 근본적으로 이 경로는 preprocessing의 학습용 조건 렌더 생성기이며, 논문 평가 입력의 30개 무작위 단위구 시점 규약이나 공식 test camera-set이라는 근거가 없다.

## 5. 현재 가능한 범위와 외부 자료 확보 후 소표본 검산

현재는 test 순서/ID, ZIP member 구조, JSON↔OBJ↔part PNG index, annotation `group_info`, 공식 전처리 경로와 카메라 생성 규칙까지 검산할 수 있다. conditioning image, camera matrix, texture, metric-ready GT map의 의미적 대응은 확정할 수 없다.

외부 자료를 표본별로 확보한 뒤에는 `metadata.csv`의 instance→local_path→`renders_cond`/`transforms.json` 대응, 파일 hash·view ID·camera matrix, ShapeNet texture 정합, 렌더 GT map/mask/channel을 CPU에서 소표본 검산할 수 있다. 그것이 확인되어도 논문 전체 평가나 30-view PSNR 동등성은 별도 조건 검증이 필요하다.
