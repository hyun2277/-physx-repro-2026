# 29806 viewpoint probe: 006 decoder-gate 경로 수정

실행 `/home/minsujo/Desktop/SH/PHYSx/logs/29806-viewpoint-probe/20260927T061911Z-4b32fcccb880`은 000의 sampling·physics decoder·mesh decoder·CPU articulation audit과 006의 sampling·CPU decoder gate까지 성공했다. 006 gate는 실제로 `steps/09_decoder_gate_006/decoder_eligibility.json`을 만들었고, latent SHA256은 `515823f2cf2459d1825af08b665549401598ab222451cd1358e10d1cb5bd9ae4`이다. 이 gate는 N=12,864, N×64=823,296, reserve 정책상 eligible=true를 기록했다.

실패는 runner가 다음 decoder 단계 전에 `steps/08_decoder_gate_006/decoder_eligibility.json`을 문자열로 조합해 읽으면서 발생한 `FileNotFoundError`다. `08`은 sampling 단계이고 gate 단계는 `09`이므로, 모델·GPU·latent·adapter 실패가 아니다.

수정된 runner는 어떤 frame에도 단계 번호를 조합하지 않는다. `Runner.step()`이 반환하는 SUCCESS marker의 `outputs`에서 basename `decoder_eligibility.json`을 정확히 하나 찾아 실제 output path를 다음 단계에 전달한다. 000과 006은 동일 loop와 같은 lookup 함수를 사용한다. marker가 output을 하나도 또는 여러 개 기록하거나 대상 파일이 없으면 fail-closed한다.

CPU self-test는 임시 `04_decoder_gate_000`과 `09_decoder_gate_006` output marker를 각각 만들고, 두 경우 모두 marker 기반 path lookup이 성공하는지 확인했다. `--resume`은 기존 run의 유효 SUCCESS marker와 output hash를 건너뛰며, 이전 failed attempt를 덮어쓰지 않는다. 이번 실패 run에서는 000 GPU 단계와 006 sampling은 재사용되고, 변경된 CPU gate marker만 새 attempt로 기록된 뒤 006 physics decoder부터 진행한다.
