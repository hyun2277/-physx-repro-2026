## 선택한 후보와 한계

`channel_tiled_spconv.py`는 기존 spconv Native `SubMConv3d`가 int32 feature 바이트 경계에 닿을 때만 입력 채널과 KRSC 가중치의 마지막 축을 동일하게 분할한다. 원래 sparse 좌표, 3×3×3 이웃, stride/padding/dilation, indice key/cache, 출력 채널과 bias를 유지한다. 타일 출력을 fp32로 합한 뒤 원래 fp16 dtype으로 되돌린다. 그룹 convolution, fused add/activation, 학습, 지원되지 않는 weight layout, 출력 자체의 int32 초과에는 즉시 실패한다. 원본 site-packages와 checkpoint는 변경하지 않는다.

이 분해는 실수 연산으로는 동일하지만 fp16 누산 순서가 다를 수 있다. 따라서 숫자 동등성은 **아직 미검증**이다. 일반 터미널 runner는 실제 실패 계층과 같은 입력 512/출력 256채널, 누락 이웃이 있는 작은 CUDA 좌표 집합에서 원본 spconv 및 독립 CPU 이웃합과 먼저 비교한다. 사전 지정 허용 오차는 원본 spconv 대비 fp16 `atol=0.02, rtol=0.02`, 독립 fp32 참조 대비 `atol=0.08, rtol=0.05`이며 결과를 본 뒤 완화하지 않는다. 실제 29354 실패 크기의 decoder 출력은 runner를 실행하기 전까지 검증되지 않는다.

공간 타일링은 이웃 halo와 원래 행 순서·indice cache 재조립이 더 복잡하다. 단순 행 분할은 경계 이웃을 잃으므로 사용하지 않는다. 정규화·잔차 연산은 분할 대상 밖에 두어 원래 전체 sparse tensor에 계속 적용한다.

## 이번 준비에서 실제 통과한 검사

- Python 구문 검사와 생성될 `example_adapter.py`의 구문·diff 검사 통과. 원본의 `SPCONV_ALGO='native'`, `seed=1`, 기본 sampling 및 해상도는 유지한다. pipeline 기본 `seed=42`는 example의 명시적 `seed=1`에 덮인다.
- CPU 독립 이웃합: 누락 이웃과 경계 좌표가 있는 25행, 입력 64채널/출력 32채널에서 전체 채널합과 32채널 분할합의 최대 절대오차 `4.263256414560601e-14`, 최대 상대오차 `1.3663052697685104e-13`.
- CPU spconv Native와 adapter 실연산 비교(25행, 64→32채널): 최대 절대오차 `2.384185791015625e-07`; 독립 fp64 참조 대비 `1.6540710567891637e-07`. CPU spconv는 fused bias를 지원하지 않아 이 검사는 bias 없이 수행했다. bias 포함 검사는 별도 수학적 참조와 일반 터미널 GPU 비교에 둔다.
- 실패 크기 산술: 전체 `2,220,752,896` bytes > int32 최대, 256채널 타일과 256채널 출력은 각각 `1,110,376,448` bytes < int32 최대.
- `--cpu-only` 실행은 원본 HEAD, pyc-only tracked 변경, 입력 PNG/transforms SHA256, 비어 있지 않은 11개 checkpoint manifest 및 실제 파일 hash, 위 CPU 검산을 통과했다. 로그: `logs/rtx5090-adapter-29354/20260926T192014Z-ce9944c53f12/`.
- adapter가 현재 설치된 `spconv.pytorch.conv.SparseConvolution.forward`를 지정 Python에서 패치하는 것과 실제 module 경로는 CPU import로 확인했다.
- `trellis` 전체 import를 이 실행 세션에서 시도하자 Warp 초기화가 NVIDIA 드라이버를 찾지 못하고 읽기 전용 사용자 cache에서 중단됐다. CUDA 연산이나 모델 추론은 시작되지 않았다. runner는 PHYSx 내부 쓰기 가능한 cache와 GPU UUID를 설정한 일반 터미널에서 실제 import 경로를 다시 확인한다.

CUDA 검사·small spconv·실제 큰 입력·물리 decoder·table 회귀 추론·29354 전체 추론·영상/GLB 검증은 **실행하지 않았다**. GPU runner가 통과하더라도 결과는 29354 한 표본의 환경 적응 추론이며 물리 정확도나 논문 정량평가가 아니다. 기존 conditioning 24뷰는 논문 외관 평가 30뷰와 다르다.

## 일반 Linux 터미널 실행기

`python3 /home/minsujo/Desktop/SH/PHYSx/repro-records/04_PhysX-3D/자료확보/run_rtx5090_adapter_29354.py`

runner는 시작 시 로그 경로와 GPU 28,000 MiB/2시간 상한을 표시한다. GPU index 1의 UUID를 확인하고 해당 UUID를 `CUDA_VISIBLE_DEVICES`에 전달하며 다른 compute process가 있으면 중단한다. CUDA 12.8.1 overlay와 GCC/G++ 12를 실행 폴더에만 구성한다. source/입력/checkpoint hash와 실제 import 경로, CPU·GPU 비교, 큰 크기 산술, 기존 table 성공 기록을 순서대로 확인한 뒤 **한 번만** adapter example을 실행한다. 예제 사본은 전처리 이미지/전경, sparse 좌표 수·범위·중복, sampled geometry/physics latent와 RNG, 원시 물리 텐서를 실행 로그에 기록한다. 출력 MP4 4개를 실제 decode하고 GLB mesh·UV·texture와 원시 물리 텐서를 재로딩한다. `result.json`은 전체 상태와 inference 상태를 따로 기록한다. 자동 push는 없다.

현재 GPU 숫자 동등성 검사가 아직 수행되지 않았으므로 이 runner는 검증되지 않은 적응 추론을 허용했다고 간주하지 않는다. 앞 단계 실패 시 전체 추론을 시작하지 않는다.
