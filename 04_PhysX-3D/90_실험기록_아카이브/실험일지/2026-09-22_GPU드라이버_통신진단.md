# 2026-09-22 GPU 드라이버 통신 진단

## 범위와 보호 조건

이번 단계는 읽기 전용 진단이다. 원본 공식 예제, 모델 추론, CUDA 변경, 드라이버 설치·삭제, GPU reset, 재부팅, sudo는 실행하지 않았다. 실행별 원본 로그는 Git 밖의 `PHYSx/logs/gpu-driver-diagnosis-20260922/20260921T173545Z/`에 보관했다.

## 관찰 결과

- `nvidia-smi`는 이 단계에서 정확히 한 번 실행했다. 실행 시각은 `nvidia-smi.ended_at.txt`와 `started_at.txt`에 기록되어 있고, stdout은 `NVIDIA-SMI has failed because it couldn't communicate with the NVIDIA driver...`, stderr는 비어 있으며 종료 코드는 `9`이다.
- `/proc/driver/nvidia/version`은 NVIDIA open kernel module `595.84`와 빌드 GCC `13.3.0`을 보고했다. `/proc/driver/nvidia/modules`는 없었고, `/proc/driver/nvidia/gpus`는 디렉터리라 단일 `cat`으로 읽을 수 없었다.
- `lsmod`에는 `nvidia`, `nvidia_modeset`, `nvidia_drm`, `nvidia_uvm`이 로드되어 있었다.
- `lspci -nnk`에는 NVIDIA VGA 장치 두 개(`01:00.0`, `02:00.0`, device `10de:2b85`)가 보이며 두 장치 모두 `Kernel driver in use: nvidia`로 표시되었다.
- 프로세스 스냅샷에는 별도의 apt/dpkg/nvcc/CUDA 작업을 확인할 수 없었다. 진단을 수행한 셸/Codex 프로세스 자체는 스냅샷에 포함되어 있다.
- `dmesg --level=err,warn`은 권한 없이 커널 버퍼를 읽을 수 없어 `Operation not permitted`(종료 코드 1)였다. `journalctl -k -b`는 읽혔지만 확인한 최근 300행에는 직접적인 `NVRM`, `Xid`, NVIDIA GPU 오류가 나타나지 않았다. 보인 AppArmor 거부는 NVIDIA 오류로 해석하지 않았다.
- `/var/run/reboot-required`가 존재하고 패키지 목록은 `linux-image-6.8.0-139-generic`, `linux-base`, `libc6`, `apparmor`였다. 이는 재부팅 필요 표식이지 NVIDIA 원인의 증거는 아니다. 재부팅하지 않았다.
- dpkg 상태에는 CUDA 12.8/13.0과 NVIDIA 595 관련 패키지 항목이 있다. 이는 패키지 메타데이터일 뿐, 현재 NVML 통신이나 실제 컴파일러 사용 가능성을 검증한 결과가 아니다.

## 원인 후보와 한계

로그가 직접 뒷받침하는 관찰은 “PCI 장치와 NVIDIA 커널 모듈 바인딩은 보이지만 `nvidia-smi`의 드라이버 통신은 실패했다”는 불일치다. 실행 중 커널과 사용자 공간 드라이버 상태의 불일치 또는 재부팅 필요 상태는 추가 조사할 후보지만 원인으로 확정하지 않는다. 권한 제한으로 `dmesg`를 읽지 못했고, 접근 가능한 journal 발췌에서 직접적인 NVIDIA 오류를 찾지 못했으므로 하드웨어·커널·NVML 중 어느 층이 원인인지 판단할 수 없다.

GPU가 다시 사용 가능하다는 확인 전에는 원본 예제 재실행 계획을 만들지 않는다.
