## 실제 구조와 test 대응

실제 경로는 준비 문서의 후보와 달랐다.

```text

version_1/partseg/<object_id>/imgs/<part>.png
version_1/partseg/<object_id>/objs/<part>.obj
```

수정한 중앙목록 점검기는 이 구조를 사용해 공식 test 1,000행을 원래 순서로 검사했다. `finaljson`·OBJ·PNG 경로를 모두 찾지 못한 행은 1개였고, test index 971 / source index 1971 / object ID `36610`이다. 이 행은 제외하지 않고 `UNRESOLVED`로 남겼다. archive 안에 다른 표기나 별도 경로가 있는지는 추가 파일 추출 없이 확인해야 한다.

## 고정·관절 후보

JSON annotation의 실제 최상위 키는 `category`, `dimension`, `group_info`, `object_name`, `parts`로 확인됐다. `group_info`에서 root `0` 이외의 비어 있지 않은 group 수를 세어 후보를 표시했다.

| 분류 | test 행 | 의미 |
|---|---:|---|
| `FIXED_CANDIDATE` | 750 | root 외 group이 없음 |
| `ARTICULATED_CANDIDATE` | 249 | root 외 group이 1개 이상 |
| `UNRESOLVED` | 1 | object `36610`, annotation/parts 경로 미발견 |

예시로 test index 0의 `7271`은 `group_info` 비-root group 3개인 관절 후보이며, index 1의 `29354`는 root만 있어 고정 후보다. 이 분류는 실제 JSON 구조에 근거한 준비용 후보이며, 저자가 제공한 fixed/articulated 분류표나 논문 평가 조건으로 확정하지 않는다. 최소 표본은 다음 단계에서 이 후보의 부품·질문·카메라·좌표 연결을 확인한 뒤 선정한다.

## 확인된 것과 아직 모르는 것

입력 PNG, 부품 OBJ, 속성 JSON은 적어도 999개 test 행에서 archive member로 연결 후보가 확인됐다. JSON 질문 필드와 `group_info` 값은 읽을 수 있지만, 공식 평가 질문의 선택 규칙과 입력 이미지의 카메라 metadata는 이 점검으로 확인되지 않았다. 별도 30-view camera-set, 완성된 숫자 GT map, texture 정합, 관절 pose 샘플도 제공 여부를 확정하지 않았다.

따라서 이번 결과는 “archive 내부 목록과 annotation 후보 연결 성공”이며, 공식 GT 평가 준비 완료나 논문 동일 조건 평가 성공이 아니다. 다음 단계는 `7271`과 `29354`를 후보로 삼아 annotation의 part label·OBJ 파일명·질문 필드·이미지 대응을 읽기 전용으로 대조하는 것이다. `finalindex.json`의 texture 경로 누락 40행도 test에서 제외하지 않고 별도 조사 대상으로 유지한다.
