# 29354 spconv 대체환경 진입 판정

## 현재 환경의 두 알고리즘 실패

- native: `logs/inference-29354-run/20260925T191900Z/`에서 `spconv-cu126 2.3.8`/`cumm-cu126 0.7.11`의 `indice_subm_conv`가 `N=2,168,704`, `C=512`, fp16 int32 assert로 종료했다.
- implicit_gemm: `logs/inference-29354-implicit-gemm/20260926T073826Z/`에서 같은 wheel 조합의 `ops.implicit_gemm`가 같은 int32 assert로 종료했다.

따라서 현재 wheel 조합에서 알고리즘 선택만으로 해결되지 않았다. 두 실행의 입력·checkpoint·source는 동일하고, 두 번째는 staging 복사본 line 3만 `implicit_gemm`으로 바꾼 경로였다.

## upstream release/source 판정

upstream spconv 2.3.8의 공식 prebuilt는 CUDA 12.6까지이며, setup dependency는 `cumm-cuXX>=0.7.11,<0.8.0`이다. changelog는 2.2.5의 large-shape overflow 수정, 2.3.x의 large-kernel/NVRTC 기능을 기록하지만 현재 오류 assert가 해결됐다는 후속 release나 issue close 근거는 없다. upstream issue #706은 동일 assert를 열어 둔 상태다.

upstream cumm의 현재 build workflow에는 CUDA 12.8 항목과 `0.8.2` 계열 source가 있지만, 그것만으로 spconv 2.3.8의 `<0.8.0` dependency와 int32 오류 해결을 입증하지 않는다. 공식 upstream에서 CUDA 12.8·Python 3.10·torch 2.7.1+cu128·sm_120용으로 함께 검증된 spconv+cumm release/commit 쌍은 확인하지 못했다.

## 판정

근거 있는 호환 쌍이 없으므로 새 환경 생성, source build, wheel 설치, native inference를 시작하지 않았다. 현재 환경과 데이터는 보존됐다. community wheel이나 dependency pin을 임의로 풀어 조합하는 것은 이번 공식 대체환경 기준에서 제외한다.

다음에 진행하려면 upstream이 spconv+cumm의 동일 ABI와 large-shape/NVRTC 수정 근거를 함께 제공하거나, 해당 수정 commit과 재현 가능한 build manifest를 먼저 확보해야 한다. 그 전까지는 설치보다 중단이 맞다.
