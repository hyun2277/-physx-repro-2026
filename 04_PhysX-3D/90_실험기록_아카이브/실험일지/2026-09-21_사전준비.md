# 2026-09-21 — 공동 재현 사전 준비

## 목적과 상태

팀원 조사 자료와 우리 설치 스크립트를 논문/공식 코드와 비교했다. 현재는 검토 단계이며 GPU 실험 결과는 없다. 주요 정량 지표 실측은 0/9이고, 성공 확률이나 논문 전체 재현율을 예측할 근거는 없다.

## 검증 증거

- 공식 기준 commit: `4f54e750a309fe9cd9f20816916ecc0e8a9ae594`.
- CPU 설정 검사: `ATTN_BACKEND=sdpa`여도 sparse attention은 flash_attn 유지. 팀원 안의 두 backend 패키지 동시 생략은 채택하지 않음.
- 공개 split: 전체 2000항목/1878고유ID, validation973/test972고유ID, 양쪽 공통67ID. 논문 실험 데이터 누수로 단정하지 않음.
- 패치3개 개별/모든6순서 적용 및 문법 통과 기록 존재. 실제 데이터/GPU 검증은 아님.
- 모델 두 저장소 메타데이터 합계15,801,449,272bytes. 환경/빌드/추가 캐시/데이터 공간 별도.
- 사용자 제공 서버 출력: Ubuntu24.04.3, RTX5090 2장, RAM125GiB, 디스크 가용496G, driver595.84, 실제 nvcc12.2.140, GCC/G++13.3. 서버에 직접 접속해 검증한 것은 아님.

## 채택 출처

팀원: 기본판/XL 분리, 가중치revision 조사, GPU 연산 검사·상세 기록 원칙.
우리: vox2seq/CLIP 등의 설치 보완, hf CLI, 출력/로그 관리, 공식 코드 결함·패치 검토.
통합 계획을 작성했지만 기존 설치 스크립트에 모든 결정이 반영된 것은 아니다.

## 첫 예제 실행 전 필수 보완

1. 사용 가능한 toolkit을 조회하고 torch/cu128 후보와 맞는 CUDA 개발 도구를 별도 환경에서 선택. 현재 nvcc12.2로 sm_120 직접 빌드하지 않음.
2. 코드 checkout/HF revision/의존성 버전 고정, 캐시/임시/출력 경로 지정.
3. 환경/컴파일러 버전 검사, pip 충돌 시 중단, 재실행 경로 충돌 방지.
4. attention dense+sparse, sparse conv, vox2seq, renderer의 실제 forward 검사. import 성공만으로 통과시키지 않음.
5. 명령/입력hash/seed/patch/exit code/GPU 점유 로그를 한 run_id로 보존.

## 논문 수치 평가 전 필수 구현

1. 관절 부모 그룹/빈 그룹 잔여 처리, GT part-mesh와 description 매핑 검증.
2. split 순서/중복 보존과 평가단위 확정; 데이터/texture/카메라/단위 확인.
3. batch 추론, 원시 물리 출력 export, GT 대조, 9개 지표 계산·집계·resume 연결.
4. NAP 관절 평가 코드 재사용/변환 조사 및 채점기 정답 테스트.
5. 실패 항목을 숨기지 않는 분모/집계, 원본과 수정본 구분.

## 후속 실험

주요 평가 뒤 baseline/ablation/필요 재학습, 제조·비주방 물체 범용성 및 촬영조건/seed 변동을 조사한다. XL과 후속 VLM 평가는 별도 확장으로 둔다.
