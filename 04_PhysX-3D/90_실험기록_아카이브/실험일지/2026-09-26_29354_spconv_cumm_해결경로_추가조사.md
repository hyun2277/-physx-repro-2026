# 29354 spconv/cumm 해결 경로 추가 조사

## 알고리즘과 checkpoint

고정 원본 `example.py:3`이 `SPCONV_ALGO=native`를 설정한다. `trellis/modules/sparse/conv/__init__.py:4-16`은 `native`, `implicit_gemm`, `auto`를 런타임 알고리즘 선택값으로만 사용하고, `conv_spconv.py:13-20`은 각각 `spconv.ConvAlgo.Native` 또는 `MaskImplicitGemm` 객체를 만든다. checkpoint 파일 구조나 tensor key를 바꾸는 선택이 아니며, 모델의 sparse feature와 출력 의미는 동일한 checkpoint를 사용한다. 다만 kernel 구현·성능·수치 경로가 달라져 결과 동등성은 별도 검증이 필요하다. 원본 example이 native를 강제하므로 환경 변수만으로 다른 알고리즘을 선택할 수 없다.

## upstream 근거

upstream issue #706은 같은 int32 assert를 기록하고 큰 voxel resolution/batch를 점검하라고 한다. changelog의 2.2.5는 큰 shape overflow 수정, 2.3.0은 large kernel 지원, 2.3.8은 CUDA 12.1/12.4/12.6 prebuilt와 NVRTC 지원을 언급하지만, 현재 2.3.8의 해당 오류를 완전히 제거했다는 릴리스 근거는 없다. setup.py는 2.3.8 계열이 `cumm>=0.7.11,<0.8.0`을 요구한다. 그러므로 cumm만 0.8.x로 교체하는 것은 공식 호환 조합이 아니다. 해결에는 같은 ABI로 빌드된 spconv+cumm 쌍이 필요하거나, shape를 줄이는 별도 모델 경로가 필요하다.

## 해상도와 checkpoint

원본 image pipeline의 voxelization은 `voxel_size=1/64`, bounds `(-0.5,0.5)`이며 sparse decoder의 mesh resolution도 checkpoint 구성에서 파생된다. checkpoint는 학습 당시 latent resolution/channel 구조를 전제로 하므로 voxel resolution이나 latent spatial structure를 임의로 줄이면 입력 shape만 줄어드는 것이 아니라 decoder 구조·mesh 출력 해상도·학습 분포가 달라진다. 현재 checkpoint에 inference-only 해상도 축소 인자는 확인되지 않았다. 따라서 해상도 축소는 논문 모델과 다른 실험이며, checkpoint 호환 해결책으로 판정하지 않는다.

## CUDA 12.8/RTX 5090 호환성

공식 PyTorch `2.7.1+cu128` cp310 Linux wheel은 확보 가능하고 현재 torch와 일치한다. upstream spconv의 공식 prebuilt 계열은 cu126까지이며, 공식 PyPI에서 현재 환경과 맞는 `spconv-cu128` 쌍은 확인되지 않았다. PyPI의 `cumm-cu128 0.8.2` cp310 wheel만 단독으로 존재하지만 upstream spconv 2.3.8 dependency pin(`<0.8.0`)과 충돌한다. 커뮤니티 cu128/sm_120 wheel은 별도 출처이며 공식 PhysX 재현 기준으로 사용할 수 없다.

## 계획(실행하지 않음)

가장 안전한 다음 단계는 현재 `physxgen`을 보존한 채 PHYSx 내부 별도 venv/복제 환경에서 CUDA 12.8, Python 3.10, GCC 12, torch 2.7.1+cu128에 맞춘 **동일 버전 cu128 spconv+cumm pair**를 source build 또는 출처가 명확한 wheel로 준비하는 것이다. 예상 build는 cumm/spconv 생성·컴파일에 수십 분에서 한 시간 이상 걸릴 수 있고, custom wheel은 ABI·sm_120·NVRTC·checkpoint 출력 동등성 위험이 있다. 설치 전에는 정확한 wheel hash, spconv↔cumm dependency pin, `import torch` 후 `import spconv`, native/implicit_gemm의 int32 경로, 실패 시 기존 wheel cache로 즉시 rollback할 수 있는지 확인해야 한다. 이 계획은 아직 설치·빌드·GPU 실행되지 않았다.

결론: 알고리즘 변경이나 해상도 축소를 먼저 선택하지 말고, 공식 cu128 쌍이 없다는 사실을 전제로 별도 환경에서 호환 spconv+cumm pair를 검증하는 경로가 가장 근거 있다. 그 경우에도 논문 동일 조건은 보존되지만, custom/community build는 공식 재현성 근거가 추가로 필요하다.
