## 직접 원인과 추가 코드 결함

`atomic_json`은 `main()` 후반부의 지역 함수였다. Python은 함수 전체에서 이 이름을 지역 변수로 분류하므로 앞선 material audit 호출 시 아직 binding이 없어 `UnboundLocalError`가 발생했다. 같은 구조로 `corners`도 static mapping 분기 안에서만 정의됐지만 diffuse projection 경로에서 사용됐다. 두 helper를 Isaac 의존성이 없는 `gui_29806_common.py` 모듈로 이동했다.

플래그 조합도 이전에는 함께 켤 수 있었다. 이제 static mapping, initialization, isolation, recovery/video 모드는 상호 배타적이며 diffuse-only는 isolation과 함께만 허용한다. 검사는 Kit app 생성 전에 수행한다.

예외 경로는 `runner_internal_exit.json`에 주 오류, 내부 return code, 마지막 phase와 미실행 phase를 기록한다. `app.close()` 실패는 별도 `cleanup_error.json`에 기록하여 원래 오류를 덮지 않는다. 진단의 exit 0은 진단 수집 완료만 뜻하며 asset 또는 영상 PASS가 아니다.

## 표시 문제의 현재 경계

확인 사실은 emissive 정적 mapping 화면이 정상이고, 초기화 뒤 red 소실과 green 줄무늬가 반복됐으며, diffuse-only prephysics PNG 한 장은 사실상 검정이었다는 것이다. material, lighting, normals, Fabric population 중 단일 원인은 아직 확정되지 않았다.

다음 bounded isolation 실행은 같은 카메라에 자산 영역 밖의 diffuse cyan cube와 emissive magenta cube를 함께 둔다. 자산 영역 pixel gate와 control pixel을 분리한다. 두 control 모두 안 보이면 camera/render sync/shared presentation, emissive만 보이면 diffuse lighting/material, diffuse control은 보이고 자산만 안 보이면 asset geometry/normals/render population 가설을 지지한다. 이 결과는 원인 후보를 좁히는 자료이며 자동 개폐 성공 판정이 아니다.

호출 순서는 prephysics → `setup_simulation(cuda:0)`/Fabric enable 직후·initialize 전 → initialize 직후·tensor 전 → tensor view 뒤 → 첫 `update_fabric=True` closed step 뒤다. tensor view 전에는 tensor 값을 `NOT_CREATED_YET`로 저장한다.

## 다음 진입 기준

isolation은 active-door target과 recorder를 실행하지 않는다. 화면 실패도 관측값으로 보존하고, binding·topology와 closed-step API가 안전한 경우 최대 10 closed step까지 원인 자료를 수집한다. binding, 입력 hash, articulation/DOF mapping 또는 finite state가 무효하면 physics를 차단한다.

정상 표시와 body↔clone 추종이 확인된 뒤 C1 probe로 진행한다. C1은 실제 limit 내부의 작은 범위를 3초 smoothstep으로 열고 닫으며 C2/C3에는 매 step closed target을 보낸다. joint position, body rotation, 화면 문 변화, inactive excursion과 root drift가 함께 통과해야 C2/C3 및 제출 영상 단계가 열린다.

## 복구 변경 비호스트 검증

- 실제 wrapper와 같은 `/tools/isaac-sim/python.sh --no-ros-env SCRIPT.py` 형식으로, 작업 디렉터리를 `/tmp`로 바꾼 뒤 runner 경로 회귀검사를 실행했다. `gui_29806_common` import와 기본·initialization·isolation·diffuse isolation·recovery 진입 경로가 모두 통과했다. wrapper는 `-I`, `-S`, `-P` 또는 `PYTHONPATH`를 사용하지 않으며 Python이 넣는 script directory로 공통 모듈을 찾는다.
- `atomic_json`과 `corners`는 Isaac/pxr/omni를 import하지 않는 공통 모듈에서 SimulationApp 생성 전에 binding된다. common SHA와 runner SHA는 wrapper manifest에 함께 기록한다.
- 입력 실패와 합성 SimulationApp startup 실패를 실제 `main()`에 주입하여 `runner_internal_exit.json`, primary error, 미실행 phase 및 return code 1을 검증했다. 상충 flag는 SimulationApp 생성 전에 거부된다.
- 캡처 파일 미생성, 0 byte, 지연 생성, 계속 변하는 크기, 손상 PNG와 정상 PNG를 실제 안정화 helper로 검사했다. capture completion 뒤에도 안정된 파일 크기, PNG signature, decode와 해상도를 확인한다.
- recorder와 app cleanup 오류는 별도 JSON에 기록하며 primary failure 기록을 바꾸지 않는다. wrapper는 Python exit code를 먼저 저장하고, code 0인 경우에만 completion stdout, completion report와 internal exit 계약을 모두 검사한다.
- 이 검증은 Isaac renderer/Hydra/Fabric host 실행을 포함하지 않는다. material audit의 실제 USD binding 값, 다섯 경계의 viewport PNG와 tensor pose는 다음 bounded host 진단에서 검증해야 한다.
