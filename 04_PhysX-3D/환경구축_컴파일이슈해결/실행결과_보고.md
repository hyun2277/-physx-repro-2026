# PhysX-3D 사전 검토 및 환경 구축 현황 — GPU 실행 전

**작성일**: 2026-09-21  
**재현 방식**: 각자 사전 조사 후 한 컴퓨터에서 공동 재현  
**예정 실행 환경**: Ubuntu 24.04.3, RTX 5090 2장 중 우선 1장, RAM 125GiB  
**검토 기준 커밋**: `4f54e750a309fe9cd9f20816916ecc0e8a9ae594`

논문 1~3과 같은 위치에서 환경·문제·원인·조치·결과를 기록한다. 현재는 사용자 제공 환경 출력과 로컬 코드 검사만 확보했으며, 서버 설치·컴파일·추론은 미실행이다. 아래 항목을 실제 실행 중 발생한 실패로 해석하지 않는다.

## 1. 실행 환경 확인

사용자가 전달한 터미널 출력에서 driver 595.84, 실제 nvcc 12.2.140, GCC/G++ 13.3.0, 디스크 가용 약 496G를 확인했다. `/usr/local/cuda`는 cuda-12.2를 가리킨다. cuda-13 링크 대상의 실제 설치 여부는 미확인이다. 서버에 직접 접속해 검사한 결과는 아니다.

## 2. 사전 검토에서 확인한 문제와 필요한 조치

### ① CUDA 개발 도구와 목표 GPU

- **확인 내용**: 현재 선택된 nvcc는 12.2다.
- **판단 근거**: SM_120 직접 컴파일 지원은 CUDA 12.8에서 추가됐다. [NVIDIA release notes](https://docs.nvidia.com/cuda/archive/12.8.0/cuda-toolkit-release-notes/)
- **필요 조치**: 기존 환경을 보존하고 선택한 PyTorch와 맞는 toolkit을 전용 환경에 연결한다.
- **결과**: 아직 조치·컴파일 미실행.

### ② SDPA 설정만으로 두 attention 패키지를 생략할 수 없음

- **확인 내용**: 팀원 계획은 SDPA로 변경하고 FlashAttention/xformers를 생략한다.
- **원인**: 공식 dense 모듈은 SDPA를 허용하지만 sparse 모듈은 허용하지 않는다.
- **검증**: CPU 설정 검사에서 dense=sdpa, sparse=flash_attn을 확인했다.
- **필요 조치/결과**: sparse까지 지원하는 backend 설치와 실제 forward 검증 필요. GPU 검증 미실행.

### ③ 누락 의존성과 버전 고정

- **확인 내용**: vox2seq 설치 경로, CLIP 등 누락 의존성은 우리 스크립트에서 보완했으나 전체 라이브러리/코드/가중치가 고정되지 않았다.
- **필요 조치**: 코드 SHA와 HF revision 고정, 호환 패키지 lock, pip 충돌 시 중단, 실제 GPU 연산 검사.
- **결과**: 기존 파일은 검토용 스냅샷이며 최종 실행본이 아니다.

### ④ 공식 관절 코드와 GT 생성 코드

- **확인 내용**: 관절 인덱싱, description 저장, meshname 재사용 문제를 검토하고 패치 3개를 생성했다.
- **검증**: 개별 및 6가지 적용 순서/문법 검사 기록이 있으며 업로드 전 개별 적용 검사를 다시 통과했다.
- **미해결**: 부모 그룹/빈 그룹, 실제 part-mesh 매핑, 질문과 GT 일치.
- **결과**: 패치 적용 가능성만 확인. 모델 정확성·GT 타당성은 미검증.

## 3. 체크포인트와 데이터

두 HF 모델 저장소 메타데이터 합계는 15,801,449,272 bytes다. 다운로드는 미실행이며 추가 캐시/환경/데이터 공간은 별도다. 공개 split 중복 및 GT 스크립트 전체 목록 순회도 확인했으므로 정량 평가 단위부터 확정해야 한다.
