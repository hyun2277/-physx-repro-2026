# CUDA/nvdiffrast 공통 환경 통합 검증

## 비교 대상과 범위

- 성공한 renderer-only JIT: `/home/minsujo/Desktop/SH/PHYSx/logs/nvdiffrast-gcc12/20260922T072351Z/`
- 네 번째 원본 table 실패: `/home/minsujo/Desktop/SH/PHYSx/logs/original-example-terminal/20260922T072948Z/`
- 두 로그의 overlay, 명령, 환경 기록을 읽기 전용으로 비교했다.
- 이번 통합에서는 GPU, `nvidia-smi`, PyTorch CUDA 연산, GPU context, `example.py`, 설치·다운로드를 실행하지 않았다.

## 확인된 차이

| 항목 | 성공 renderer-only JIT | 원본 table 실패 | 판정 |
|---|---|---|---|
| `bin/nvcc` | toolkit `bin/nvcc` 링크 | toolkit `bin/nvcc` 링크 | 동일 |
| `bin/cicc` | `nvvm/bin/cicc` 링크 | 없음 | **확정된 원인 차이** |
| `bin/nvlink`, `ptxas`, `fatbinary` | toolkit `bin` 링크 | 없음 | 성공 조건에 포함 |
| `include` | target include 링크 | target include 링크 | 동일 |
| `lib`, `lib64` | target lib 링크 | target lib 링크 | 동일 |
| `nvvm`, `targets` | toolkit `nvvm`, target 링크 | 같은 링크 | 동일 |
| `CUDA_HOME`, `CUDACXX` | run별 overlay | run별 overlay | 동일 구조 |
| `PATH` | overlay/bin 선두 | overlay/bin 선두 | PATH만으로는 `cicc`를 찾지 못함 |
| `CC`, `CXX`, `CUDAHOSTCXX`, `NVCC_CCBIN` | GCC/G++ 12 절대 경로 | GCC/G++ 12 절대 경로 | 동일 |
| `TORCH_EXTENSIONS_DIR` | run 아래 `torch-extensions` | 기록·명시 없음 | 성공 조건 차이 |
| `TORCH_CUDA_ARCH_LIST` | `12.0` | 미설정 경고 | 성공 조건 차이 |
| `CUDA_VISIBLE_DEVICES` | 빈 값 | `1` | renderer-only와 원본 목적 차이 |
| extension 이름 | `nvdiffrast_plugin_gcc12_probe` | `nvdiffrast_plugin` | 검사 이름만 다름 |
| 소스 목록 | nvdiffrast 15개 소스 | 같은 nvdiffrast 15개 소스 | 동일 계열 |
| C++ 옵션 | `-DNVDR_TORCH`, `-fPIC`, `-std=c++17` 등 | 동일 | 동일 |
| CUDA 옵션 | `-lineinfo`, `-gencode=arch=compute_120,code=sm_120` | `-lineinfo`, 자동 `compute_120`+`sm_120` | arch 선택 차이 |
| 결과 | 종료 코드 0, JIT load 완료 | 종료 코드 1, `sh: 1: cicc: not found` | 실패 원인 확정 |

성공 검사와 실패 실행 모두 `-ccbin /usr/bin/gcc-12`, CUDA 12.8.1 `V12.8.93`, target runtime header/lib를 사용했다. 따라서 네 번째 실패는 `_Float32`나 GCC 12 선택 문제가 아니라, overlay에서 CUDA 내부 실행 파일 `cicc`를 찾지 못한 환경 구성 차이로 판정한다.

`TORCH_EXTENSIONS_DIR`와 `TORCH_CUDA_ARCH_LIST` 차이는 원본 실패의 직접 오류인 `cicc` 누락과는 별개인 재현성 차이다. 원본의 미설정 arch는 로그의 PyTorch 경고와 자동 `compute_120`/`sm_120` 두 플래그로 확인했다. “이 차이가 실패를 일으켰다”는 것은 추정이며, 현재 로그가 직접 입증하는 것은 `cicc` 누락뿐이다.

## 통합 구현

공통 스크립트 `04_PhysX-3D/실행스크립트/cuda_jit_environment.sh`를 추가했다. `cuda_jit_prepare`는 매 실행 폴더 아래 overlay를 만들고 다음 링크를 함께 구성한다.

```text
bin/nvcc, bin/cicc, bin/nvlink, bin/ptxas, bin/fatbinary
include, lib, lib64, nvvm, targets
```

또한 CUDA_HOME, CUDACXX, PATH, GCC 12 host compiler 네 변수, `TORCH_EXTENSIONS_DIR`, `TORCH_CUDA_ARCH_LIST=12.0`을 해당 프로세스 환경에만 export한다. `run_original_table_terminal.sh`와 기존 renderer-only `run_nvdiffrast_gcc12_compile.sh`가 이 공통 함수를 source해 사용하도록 연결했다.

## 검증

- 세 스크립트 `bash -n` 통과
- 임시 폴더에서 공통 함수가 다섯 `bin` 링크와 다섯 overlay 경로를 만들고 실제 대상이 존재하는지 확인
- `cicc`가 정확히 `toolchains/cuda-12.8.1/nvvm/bin/cicc`로 해석됨을 확인
- `TORCH_EXTENSIONS_DIR`가 임시 run 아래이고 `TORCH_CUDA_ARCH_LIST=12.0`임을 확인
- 원본 source, system CUDA, pretrain, 모델, 데이터는 수정하지 않음

이번 네 번째 원본 table 실행은 미완료 상태로 남겼다. 이후 검증은 공통 환경을 기준으로 하며, 오류별 원본 예제 반복 실행은 중단한다.
