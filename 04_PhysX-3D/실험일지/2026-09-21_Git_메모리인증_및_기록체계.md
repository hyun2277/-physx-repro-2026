## 실패·원인·조치·재실행 결과

- 이전 push는 sungmoon2에 대한 저장소 쓰기 권한 부족(403)으로 실패했다. 사용자 요청에 따라 그 계정의 권한을 추가하거나 로그인 상태를 바꾸지 않았다.
- 인증 helper 검토에서 캐시가 없을 때 기존 askpass/터미널로 넘어갈 수 있는 경로를 발견했다. `quit=true`로 중단하도록 수정했고 모의 검사로 확인했다.
- cache 저장 요청이 시간 초과된 뒤에도 토큰이 남을 가능성을 검토했다. 저장 시도 전 정리 대상으로 표시하고, 실패 시 전용 cache 종료 및 빈 상태 확인을 수행하도록 수정했다.
- 일반 cache helper는 성공 인증 후 보관 시간이 갱신될 수 있다. 전용 helper의 store를 무시하여 **login 때만 28800초를 지정**하도록 수정했다. 사용 중 자동 연장은 하지 않는다.
- 제한 환경의 상태 조회 실패는 명령 단위 승인 후 재시도에서 해결됐다. 전체 보호 설정을 풀거나 다른 인증 저장소로 대체하지 않았다.

## 사용·종료 방법과 검증 한계

실행 도구는 `PHYSx/logs/git-records-20260921/physx_auth_session.py`이다. [검토용 코드](../증거/2026-09-21_Git_메모리인증/physx_auth_session.py)와 [모의 검사 코드](../증거/2026-09-21_Git_메모리인증/auth_session_security_checks.py)를 보존했다.

- `login`: 사용자가 직접 터미널에서 토큰을 숨김 입력한다. 비대화형 입력이나 숨김 입력 실패 시 중단한다. GitHub `/user`가 hyun2277인지 확인한 뒤 토큰을 전용 daemon 메모리에 넣는다. 토큰은 파일·로그·환경 변수·명령 인자에 쓰지 않는다.
- 유지 시간: login의 저장 요청부터 8시간. 사용으로 갱신하지 않으며, 재부팅·daemon 종료·토큰의 서버 만료로 더 일찍 사용할 수 없게 될 수 있다. 실제 만료 시각은 로그인 성공 시 출력한다.
- `status` 또는 `status --verify`: 인증값을 출력하지 않고 존재 여부와 검증 상태만 확인한다. 사용자명 설정 자체는 계정 인증의 증거가 아니다.
- `stop`: `/home/minsujo/Desktop/SH/PHYSx/tmp/gh-hyun2277/socket`의 전용 cache만 종료하고 비었는지 확인한다. 서버의 PAT를 폐기하거나 선배의 로그인·전역 설정을 바꾸지 않는다.
- 작업을 완전히 마치면 GitHub에서 이번 작업용 PAT도 폐기한다. 브라우저 로그아웃은 토큰 폐기를 대신하지 않는다. 이 저장소에 추가한 인증 설정의 원복은 별도 단계이며 기존/이후 변경을 비교한 뒤 이 작업의 값만 처리한다.
- 같은 Linux 계정의 다른 프로세스와 완전히 격리된다는 보장은 없다. helper get이나 git credential fill을 터미널 또는 일반 로그 수집 경로에서 직접 실행하지 않는다. 비밀 전달 스트림은 로그 대상에서 제외한다.
- 실제 토큰 계정 인증과 원격 fetch는 위와 같이 성공했다. 일반 push와 원격 SHA 대조도 아래와 같이 성공했다. 실제 daemon의 8시간 경과 및 stop 명령에 의한 종료는 아직 검증하지 않았다. 모의 검사는 이 미검증 범위를 대신하지 않는다.
