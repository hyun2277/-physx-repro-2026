# PhysXNet 로봇팔 관절 후보 읽기 전용 조사

## 범위

이 조사는 공개 PhysXNet ZIP의 중앙 목록과 실제 `finaljson`, 고정 공식 source의
`tools/finalindex.json`, 기존 1,000-row eligibility manifest만 읽었다. 다운로드,
압축 해제, Blender/GPU 실행, 추론, 시뮬레이터 실행과 파일 수정은 하지 않았다.

## 방법과 결과

기존 manifest의 마지막 test 1,000행을 유지해 각 ID의
`version_1/finaljson/<id>.json` 존재를 중앙 목록으로 확인했다. 999개 JSON은 실제로
읽을 수 있었고, 36610은 ZIP에 해당 JSON member가 없어 `SOURCE_MISSING`으로 남겼다.

각 실제 JSON에서 다음 명시 근거를 `object_name`, `category`, part `name`, 그리고
part description field에 대해 대소문자 구분 없이 검색했다.

* `robot`
* `manipulator`
* `gripper`
* `end effector` / `end-effector`

결과는 **0건**이었다. `arm`이라는 단어 자체는 armchair, chair armrest, desk-lamp
arm처럼 가구·조명 part에서 많이 나타났지만, robot arm·manipulator의 명시 label이나
구조적 근거가 아니다. 따라서 fixed base 외 B/C 관절과 parent/direction/position/range를
갖춘 **로봇팔** 후보 표에는 넣지 않았다.

| 적격 PhysXNet robot arm 후보 | object ID | 관절 구조 | ShapeNet archive | texture 상태 |
|---|---|---|---|---|
| 없음 | — | — | — | — |

finalindex mapping은 실제 JSON이 있는 모든 행에서 읽기 전용으로 대조했지만, mapping이
있더라도 JSON annotation이 로봇팔을 명시하지 않으면 후보로 승격하지 않았다. 따라서
가장 단순한 실행 후보도 선정하지 않았고, 노트북 10163과 같은 재현 흐름의 preflight를
만들지 않았다.

## 결론

**현재 공개 PhysXNet test 자료에서 robot arm 예시를 확인하지 못했다.** 이 결론은
로봇팔 label/annotation을 찾지 못했다는 뜻이며, ShapeNet category 번호·모델 ID·파일명만
보고 다른 물체를 로봇팔이라고 추정하지 않았다. 별도 로봇 데이터나 시뮬레이터 영상은
PhysX-3D generated output과 분리된 후속 시연이므로 이번 조사 범위에 포함하지 않았다.
