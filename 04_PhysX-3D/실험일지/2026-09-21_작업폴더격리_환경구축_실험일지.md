### ① Codex 실행 경계의 DNS·namespace 제한

- **실패:** 최초 기록 저장소 clone은 `Could not resolve host: github.com`, exit128이었다. 이후 공개 metadata 조회에서도 sandbox DNS 오류가 있었다.
- **조치·결과:** 필요한 동일 명령에 대해 명령별 sandbox 밖 실행 승인을 받아 재시도했다. clone은 exit0이었다. 보호 설정이나 TLS 검증을 변경한 해결이 아니다.
- **별도 실패:** 강화한 bwrap 실행은 sandbox 안에서 `No permissions to create new namespace`로 실패했다. 최종 격리 dry-run의 첫 시도도 같은 이유로 exit1이었으며 Conda는 시작되지 않았다.
- **조치·결과:** 승인된 실행에서도 bwrap 격리 자체를 유지했다. OS namespace 정책을 변경하거나 격리를 제거하지 않았다. 이후 probe와 격리 dry-run은 성공했다.

### ② Conda 설정·repodata 처리

- **실패:** Conda 23.3.1에서 `CONDARC=/dev/null`을 사용한 첫 dry-run은 config 로더의 `KeyError:8192`, exit1로 끝났다.
- **조치:** PHYSx/logs의 작업용 `preview.condarc`를 지정했다. 사용자 전역 `.condarc`는 수정하지 않았다. 이것만으로 다른 모든 Conda 설정 읽기가 차단된다고 판단하지 않았다.
- **별도 실패·조치:** 기본 current_repodata 응답 처리 중 `JSONDecodeError`, exit1이 발생했다. `--repodata-fn repodata.json`으로 재시도하여 exit0을 확인했다. 원인을 `noarch404`로 단정하지 않는다.
- **추가 보완:** 실제 설치 전에는 `--no-default-packages --copy`와 exact spec을 포함한 새 격리 dry-run을 다시 통과해야 하도록 했다. [미리보기 비교](../증거/2026-09-21_작업폴더_환경구축/conda-final-isolated-preview.comparison.json).

### ④ Python 미리보기의 중단과 범위

### ⑤ 실제 CUDA 설치의 HOME 등록 경고

Conda는 읽기 전용 `~/.conda/environments.txt`에 환경을 등록하지 못했다. 예상한 외부 HOME 기록 제한이며 실제 설치 종료 코드는 0이었다. 등록 파일을 writable로 바꾸거나 HOME을 변경하지 않았다. 전용 prefix 절대경로로 Toolkit을 사용한다. [설치 stderr](../증거/2026-09-21_작업폴더_환경구축/cuda-install.stderr.log), [명령·시각·종료 코드](../증거/2026-09-21_작업폴더_환경구축/cuda-install.command.json).

## 이번에 하지 않은 것과 다음 단계

CUDA 소스 컴파일, linker/ABI 검증, 확장 패키지 빌드, CLIP 패치의 실제 소스 적용, 모델 본체 다운로드, GPU 추론·학습·정량 평가는 이 기록의 수행 결과에 포함되지 않는다. 주요 9지표 측정값은 없다.

기본 Python 패키지의 별도 설치 결과를 기록한 뒤, 후속으로 승인된 범위에서 확장별 빌드와 실제 연산을 검증해야 한다. FlashAttention dense/varlen, spconv/cumm의 RTX 5090 경로, renderer·vox2seq·Kaolin, GT/관절·split·평가기 연결은 미해결 또는 별도 검증 대상으로 유지한다. Toolkit 설치 성공은 모델 재현 성공을 뜻하지 않는다.
