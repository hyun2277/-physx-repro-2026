# PhysX-3D 실행 기록과 공유 규칙

작성일: 2026-09-21 (Asia/Seoul)

사용자가 요청한 상시 기록 기준이다. 이 문서 작성 자체는 설치·빌드·GPU 실험의 실행 또는 성공 증거가 아니다. 실제 실행에는 해당 단계의 승인과 준비 조건이 별도로 필요하다.

## 1. 실행별 원본 기록

작업 루트는 `/home/minsujo/Desktop/SH/PHYSx`이다. 설치·빌드·실험의 **각 실행 및 재시도마다** 고유한 `run_id`를 만들고 `PHYSx/logs/<run_id>/`에 다음 파일을 남긴다. 기존 시도의 로그를 덮어쓰지 않는다.

| 파일 | 기록할 내용 |
| --- | --- |
| `command.json` | 비밀값이 없는 argv, cwd, 실행 목적, 시작 시각과 시간대, 승인 범위, 제한된 환경 정보 |
| `stdout.log` | 해당 실행의 표준 출력 |
| `stderr.log` | 해당 실행의 표준 오류 |
| `result.json` | 시작·종료 시각, 경과 시간, 실제 프로세스 종료 코드, 종료 signal, 성공·실패·중단 상태, 증거 경로 |
| `environment.json` | Python·패키지·CUDA·컴파일러 등 필요한 버전, 소스 commit, 변경 patch, 설정·입력·seed·SHA256 |
| `artifacts.json` | 결과물 위치, 파일 크기, SHA256, 생성 run_id 및 공개 여부 |

- `tee`나 로그 수집기의 성공을 실행 명령의 성공으로 대신 기록하지 않는다. 실제 자식 프로세스 종료 코드를 보존한다.
- 중단·시간 초과·강제 종료로 종료 코드를 확보하지 못했으면 `unknown`과 이유를 기록한다. 임의로 성공 또는 0을 쓰지 않는다.
- 의존성 조회·미리보기·설치·import·빌드·GPU 실행·재현 지표 달성을 각각 구분한다. 앞 단계의 성공을 뒤 단계 검증으로 표현하지 않는다.
- 환경 변수 전체, shell history, 인증 파일, HTTP 인증 헤더는 수집하지 않는다. 버전과 필요한 비밀 없는 경로·설정만 명시적으로 선택한다.
- 토큰 숨김 입력 및 Git credential helper의 비밀 전달 stdout은 일반 실행 로그 수집의 **대상에서 제외**한다. 인증은 계정 확인 여부, 성공/실패, 상태 코드 등 비밀 없는 사건만 기록한다.
- 명령 인자에 인증정보를 넣지 않는다. 일반 출력에 예기치 않은 인증정보가 포함될 가능성이 있는 실행은 비밀을 파일에 쓰지 않도록 수집 방식을 먼저 준비한다. 공개 전에도 반드시 검토한다.

## 2. GPU 실험 사용량

GPU 실험이 승인된 경우에만 해당 run_id 안에서 사용량을 함께 기록한다. 실험 전·실행 중·종료 후 GPU 번호/UUID, GPU 사용률, 메모리 사용량과 총량, 온도·전력을 일정 간격으로 수집한다. 기본 간격은 1초이며 변경 시 기록한다.

- `gpu-usage.csv`, `gpu-monitor.stderr.log`, `gpu-monitor-result.json`을 실험 명령의 stdout/stderr와 분리한다.
- 모니터 명령·시작/종료 시각·종료 상태를 기록하고, 실험 종료 시 이번에 시작한 모니터만 종료한다.
- GPU 전체 사용량에는 다른 연구 작업의 부하가 포함될 수 있다. 실험 PID를 확인할 수 있으면 PID별 GPU 메모리도 구분한다. 전체 부하를 모두 우리 실험의 부하로 해석하지 않는다.
- 사용량 모니터링 실패는 별도로 보고한다. 측정하지 못한 구간이나 최대값을 추정으로 채우지 않는다.
- GPU 실험을 실행하지 않은 단계는 `GPU 실행/사용량 측정: 미실행`이라고 적는다. 이 규칙을 작성했다는 이유로 지금 GPU 실험을 시작하지 않는다.

## 3. 의미 있는 단계의 실험일지

논문 1~3의 작성일·환경·commit, 증상→원인→수정→재실행 형식과 04의 목적·시각·결과·검증 한계 형식을 따른다. 성공과 실패 모두 기록한다.

```markdown
# YYYY-MM-DD — 작업명

## 목적과 상태
승인 범위, 성공/실패/중단/미실행 상태.

## 환경과 입력
run_id, 시각·시간대, 작업 경로, Python/도구 버전,
소스 commit·patch, 입력·설정·seed·SHA256.

## 명령과 실제 결과
| 시도/run_id | 명령 또는 command.json | 시작·종료 | exit/signal | 결과 | 증거 |
| --- | --- | --- | --- | --- | --- |

## 실패·원인·조치·재실행 결과
- 증상과 오류:
- 원인: 확인됨 / 추정 / 미확인.
- 수정 내용과 근거:
- 재실행 run_id와 결과:

## 검증 증거와 한계
확인한 범위, 미실행 범위, 보존 검사, 결과 위치·크기·SHA256.

## 기록 공개 상태
선별 파일, 원격 변경 검토, 로컬 commit,
일반 push 결과, 확인한 원격 commit 또는 실패 이유.
```

기록을 빠뜨린 과거 실행은 남은 증거만으로 복원하고 누락을 표시한다. 존재하지 않는 stdout/stderr나 종료 코드를 사후에 만들어 채우지 않는다.

## 4. 큰 파일과 공개 범위

환경·다운로드 캐시·모델·대형 데이터·결과 본체는 `repro-records` 밖 작업 루트 내부에 보관한다. Git에는 관련 코드, 비밀 없는 설정, 정리된 일지, 검토한 필수 소형 로그와 manifest만 올린다.

대형 산출물의 manifest에는 작업 루트 기준 상대 위치, 파일 크기, SHA256, 생성 run_id를 기록한다. 폴더는 파일별 상대 경로/크기/SHA256 manifest와 그 manifest의 SHA256을 사용한다. 확인하지 않은 hash는 미확인으로 남긴다. 절대 경로를 공개할 때는 인증정보나 불필요한 개인 정보가 없는지도 검토한다.

## 5. commit·push와 인증 실패 보존

1. 원격 주소·브랜치·작업 상태를 확인하고, 현재 허용된 인증으로 fetch한 뒤 다른 사람이 올린 변경을 검토한다.
2. 기록 작업은 `04_PhysX-3D/` 안에서 이번 작업이 소유한 파일만 대상으로 한다. 논문 1~3, 최상위 README, 다른 사람의 변경 파일은 수정하거나 커밋하지 않는다.
3. 비밀정보·불필요한 대형 파일·범위 밖 변경을 검토하고, `git add .` 대신 파일을 하나씩 명시한다. staged 목록과 diff를 확인한 뒤 commit한다.
4. 기존 commit을 보존하고 일반 push만 수행한다. 원격 변경이 있으면 검토하여 반영하며 강제 push하지 않는다. 원격 반영을 확인한 뒤 커밋 번호와 링크를 보고한다.
5. 인증 만료·권한 부족·네트워크 오류로 push가 실패해도 stdout/stderr와 종료 상태, 일지, 로컬 commit을 보존한다. 업로드되지 않았음을 명시하고 필요한 인증 단계만 안내한다. 기록 삭제, reset 또는 커밋 재작성으로 해결하지 않는다.
6. 로컬 commit 성공과 원격 push 성공을 구분한다. 미공개 commit 링크를 업로드 완료 링크처럼 안내하지 않는다.

선배 계정의 로그인·저장된 인증정보·전역 Git 설정을 보존한다. hyun2277 인증은 이 저장소 전용 방식만 사용하고, 토큰을 파일·로그·Git에 저장하지 않는다. 작업 종료 시 전용 메모리 캐시 종료와 GitHub 토큰 폐기를 구분한다. 브라우저 로그아웃은 토큰 폐기를 대신하지 않는다.
