## 헤더와 설치 기록

`cuda_runtime_api.h`는 존재한다.

```text
/home/minsujo/Desktop/SH/PHYSx/toolchains/cuda-12.8.1/targets/x86_64-linux/include/cuda_runtime_api.h
```

파일 크기는 655,943 bytes다. 반면 `/home/minsujo/Desktop/SH/PHYSx/toolchains/cuda-12.8.1/include/cuda_runtime_api.h`는 없다. Conda 레이아웃의 target include 디렉터리와 JIT가 사용한 prefix-level include 디렉터리가 일치하지 않는다.

현재 prefix의 `conda-meta`에는 다음 개발 헤더 패키지가 이미 기록되어 있다.

```text
cuda-cudart-dev_linux-64 12.8.90 0
```

이 패키지의 설치 기록과 캐시 inventory는 `targets/x86_64-linux/include/cuda_runtime_api.h`를 파일 목록에 포함한다. 패키지 archive의 정확한 크기는 381,830 bytes이며, metadata의 설치 파일 합계는 746,033 bytes다. 의존성은 다음 네 항목이다.

```text
cuda-cccl_linux-64
cuda-cudart-static_linux-64
cuda-cudart_linux-64
cuda-version >=12.8,<12.9.0a0
```

따라서 확인된 사실은 “개발 헤더 패키지 미설치”가 아니라 “설치된 헤더가 target 경로에만 있고 JIT의 include 경로에 노출되지 않음”이다. `cuda-cudart-dev` 자체는 runtime library와 pkg-config 파일을 제공하며, 해당 헤더 파일을 prefix-level `include`에 추가하는 패키지로 확인되지 않았다.

## 설치 계획과 다음 단계

기존 CUDA 12.8.1 계획은 `cuda-cudart-dev_linux-64=12.8.90=0`을 포함했고, 해당 archive가 작업 폴더 `cache/conda`에 이미 있다. 그러므로 동일 package를 다시 설치하는 것이 이번 증거에서 필요한 다음 단계라고 볼 수 없다. 설치를 재개하기 전에 작업 폴더 전용 실행 환경에서 CUDA target include 경로를 JIT compiler의 include 검색 경로에 연결하는 설정을 먼저 검토해야 한다. 그 설정 검토가 통과한 뒤에만, 필요성이 새로 확인될 경우 위 exact package를 오프라인 cache에서 대상으로 삼는다.

시스템 CUDA 경로, 원본 소스, `pretrain/`, 모델, 데이터는 변경하지 않았다. 정량 평가와 원본 예제 완료 판정은 보류한다.
