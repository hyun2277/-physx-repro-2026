# 29354 공식 호환 환경 최종 근거 조사

## 공식 PhysX-3D 자료에서 확인된 환경

고정 source `4f54e750a309fe9cd9f20816916ecc0e8a9ae594`의 `setup.sh`는 새 환경에 Python 3.10, PyTorch 2.4.0, `pytorch-cuda=11.8`을 설치한다. `--spconv`는 PyTorch CUDA major 11이면 `spconv-cu118`, major 12이면 `spconv-cu120`을 설치한다. 공식 README도 이 setup 경로만 안내하며 5090, sm_120, CUDA 12.8, `cumm` 버전을 제시하지 않는다.

공식 GitHub README는 pretrain 다운로드 후 `python example.py` 실행과 평가 스크립트만 설명한다. 저장소에는 고정된 requirements/conda/Docker/GitHub Actions 환경 파일이 없고, 현재 고정 checkout은 grafted 단일 commit이라 변경 이력을 로컬에서 대조할 수 없었다. 공개 GitHub 저장소에는 열린 Issue가 1개뿐이며 Issue 생성은 제한되어 있었다. 프로젝트 페이지와 공개 checkpoint 설정에서도 5090/CUDA 12.8 실행 근거는 찾지 못했다.

## 현재 29354 재현 기록

- GPU: 이전 일반 터미널 확인 기준 RTX 5090 2장. 이번 실패 실행은 `CUDA_VISIBLE_DEVICES=1`을 사용했다.
- Python 환경: `physxgen`, torch `2.7.1+cu128`, runtime CUDA `12.8`.
- installed sparse wheels: `spconv-cu126 2.3.8`, `cumm-cu126 0.7.11`.
- conditioning input: 기존 `renders_cond/29354_/000.png`; checkpoint와 입력 hash는 각 runner 로그에 보존.
- native 로그: `logs/inference-29354-run/20260925T191900Z/`; `example.py`가 native를 출력한 뒤 `indice_subm_conv`에서 int32 assert로 종료.
- implicit_gemm 로그: `logs/inference-29354-implicit-gemm/20260926T073826Z/`; staging 복사본 line 3만 변경했고 `ops.implicit_gemm`에서 같은 int32 assert로 종료.
- 두 실패의 직접 shape: `N=2,168,704`, `C=512`, fp16. 계산량 `2,220,752,896` bytes가 int32 최대값을 넘는다.

공식 upstream spconv의 release/changelog는 CUDA 12.6 prebuilt와 NVRTC를 언급하지만 CUDA 12.8·RTX 5090용 공식 spconv+cumm 쌍이나 이 int32 assert를 해결한 release/저자 답변은 확인되지 않았다. upstream setup은 spconv 2.3.8에 cumm `<0.8.0`을 요구한다. 따라서 현재 5090에서 막히는 정확한 이유는 공식 PhysX 환경이 5090/12.8을 지원한다는 근거 없이, cu126 sparse wheel의 cumm int32 제한을 2.17B fp16 activation에서 만난 것이다.

## 결론

공식 호환 환경: **공개 근거 미확인**. 현재 조건에서 제안할 수 있는 공식 버전·하드웨어·설치 방법은 없다. community wheel, 임의 dependency pin 해제, 해상도 축소는 공식 저자 환경이나 논문 동일 조건으로 분류하지 않는다.
