## 설치 전 검사와 격리

외부 파일시스템을 읽기 전용으로 유지하는 기존 전용 실행기 안에서 실행했다. HOME을 바꾸지 않았고 GPU 장치를 노출하지 않았다. 설치 직전 격리 probe와 입력 파일 hash, 기존 배포판 목록을 다시 확인했다.

지정 Python을 `-I -B -S`로 시작하고 작업용 `pip_without_site.py`를 통해 pip만 실행했다. 이 방법으로 설치된 `.pth`, `sitecustomize.py`, `usercustomize.py`의 자동 실행을 피했다. 패키지 검사는 wheel ZIP의 METADATA와 설치된 dist-info를 읽는 방식이었으며 PyTorch·torchvision·Kaolin 등의 import 검증이 아니다.

1. 미리보기 metadata의 활성 의존성 267개를 대조했다. 누락·버전 조건·Requires-Python 등 검사에서 issues는 0개였다.
2. `--only-binary=:all: --require-hashes --no-index`로 승인된 URL의 wheel 169개를 PHYSx 아래에 다운로드했다. 이 단계의 `--no-index`는 index 검색을 막는 옵션이며, 명시한 HTTPS URL 다운로드에는 네트워크를 사용했다.
3. 받은 각 wheel의 SHA256을 직접 계산해 lock과 대조했다. 실제 파일 목록·wheel tag·패키지명·버전·METADATA를 검사하고, 실제 wheel의 활성 의존성 267개도 issues 0개임을 확인했다.
4. 로컬 `file://` wheel과 hash만 적은 lock으로 설치 전 offline dry-run을 수행했다. 예상 169개와 정확히 일치했고 추가·누락·버전 변경은 없었다. 이 단계까지 대상 환경은 바뀌지 않았다.
5. 같은 로컬 wheel lock과 `--no-compile --no-index --only-binary=:all: --require-hashes`로 실제 설치했다.
