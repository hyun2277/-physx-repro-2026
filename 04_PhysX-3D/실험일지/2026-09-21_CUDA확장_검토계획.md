## 문제·원인·수정·재확인

- 기존 설치 후보 목록만으로는 “공식 기본 출력에서 즉시 필요”와 “선택한 분기에서 필요”가 섞여 있었다. 고정 소스의 지연 import와 호출 경로를 확인해 vox2seq/diffoctreerast를 조건부로 분리했다. 원래 통합 문서와 과거 기록을 덮어쓰지 않고 판단 근거를 새 문서에 남겼다.
- source 기본 attn_mode와 실제 checkpoint 설정이 같다는 증거는 부족하다. 고정 checkpoint 설정 전체 대조 전 vox2seq를 무조건 생략 가능하거나 필수라고 단정하지 않는다.
- cumm의 arch 목록만으로 cu126 wheel의 SM120 실행 불가를 확정하지 않았다. PTX 우회 경로가 있지만 실제 wheel의 PTX/NVRTC/ELF 구성은 여전히 미확인이다. 이 바이너리 내용 검사를 먼저 배치했다.
- nvdiffrast는 pip 설치와 첫 CUDA JIT가 별개이며 arch 환경 변수를 지우므로, 기존 GPU 숨김 빌드로는 충분하지 않다. 원본 pin을 유지하고 단일 GPU 첫 JIT+검사를 분리하는 계획을 채택했다. 실제 실패를 발생시켜 확인한 것은 아니다.
- diffoctreerast의 단순 voxel settings 불일치 가능성은 PhysX의 EasyDict/trivec 경로에 그대로 적용되지 않았다. 이를 전체 renderer 실패라고 기록하지 않았다.
- 일부 고정 raw source의 웹 캐시 조회가 실패해 동일 SHA의 공식 raw URL을 읽는 방식으로 확인했다. 설치·빌드·GPU 실패 또는 재시도가 아니다. 원문 조회별 stdout/exit이 모두 보존된 것은 아니며 사후에 만들어 채우지 않았다.
- 독립 검토에서 필수/조건부 분류, FlashAttention 실제 packed 6개 API, spconv1×1의 torch.mm 우회 제외, 미구현 runner와 미래 명령 구분을 확인했다. 실제 확장 호환성 통과를 주장하지 않는다.
