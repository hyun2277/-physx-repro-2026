# PhysX 공식 GT 최소 표본 확보 방법 검토 — 2026-09-21

**현재 자료만으로 공식 test의 고정 물체 1개·관절 물체 1개를 확정할 수 없다. 기본 배포는 16.31 GB ZIP이고, 개별 물체의 부분 다운로드·표본 용량·질문/카메라 대응은 미확인이다.** 이번에는 기존 조사·로컬 목록·공개 문서/파일 목록만 읽었다. 데이터 payload·ZIP 중앙목록·Range 바이트·모델은 다운로드하지 않았고, 추론·평가·추가 구현도 하지 않았다.

## 1. 재사용한 근거와 필요한 파일

기준은 [기존 입력·GT 대응 규약](../평가규약/2026-09-21_초안/입력-GT-대응.md)과 [평가 규약](../평가규약/2026-09-21_초안/평가규약.md)이다. 공식 데이터 revision `ca1f6d3f5cfb5c39dc183251a3a2999dcb42e093`의 [기존 API 메타데이터](https://huggingface.co/api/datasets/Caoza/PhysX-3D/revision/ca1f6d3f5cfb5c39dc183251a3a2999dcb42e093?blobs=true)·[공식 설명](https://huggingface.co/datasets/Caoza/PhysX-3D)을 재사용했다. 이번 웹 조회에서 고정 revision/API 일부 URL은 접근 오류였으므로 새 전체 목록 조회 성공으로 기록하지 않는다. [main 파일 목록](https://huggingface.co/datasets/Caoza/PhysX-3D/tree/main)의 표시 revision `ca1f6d3`는 기존 값과 같았다.

아래 경로는 **공식 설명/코드에서 유도한 후보**이며, ZIP 안의 해당 test ID 실물을 검사한 결과가 아니다.

| 필요한 자료 | 제공 여부·후보 경로 | 실제 연결을 막는 문제 |
|---|---|---|
| 공식 test 목록 | 기존 로컬 `val_test_list.npy`의 뒤 1,000항목, 원본 hash·순서·중복 검증 완료 | 고정/관절 분류와 입력 뷰 선택은 이 목록에 없음 |
| 입력 이미지 | 설명상 `partseg/<id>/img/*.png` 제공 | ID별 파일 존재/개수, 어느 영상이 평가 입력인지, 카메라와의 대응 미검증. 최소 한 입력을 고르더라도 공식 선택 규약을 확인해야 함 |
| 모든 부품 메시 | 설명상 `partseg/<id>/objs/*.obj` 제공 | 선택 물체의 모든 OBJ 및 참조 MTL/texture가 있는지 확인 필요. 파일명 숫자·JSON label·배열 순서를 동일시하지 않음 |
| 물성/관절 annotation | 설명상 `finaljson/<id>.json` 제공 | dimension·density·priority_rank·parts·group_info 실물 필요. 고정/관절 구분과 axis/origin/range/parent-child 대응을 여기서 확인해야 함 |
| 질문 자료 | annotation에 Basic/Functional/Movement 설명 필드가 안내됨 | 공식 평가의 질문 문자열·유형·대상 부품 선택표는 확인되지 않음. annotation 설명을 직접 선택한 질문은 제안 조건이지 공식 질문표가 아님 |
| 입력/평가 카메라 | 생성 코드에는 `transforms.json` 저장 경로가 있음 | 배포 `img`에 대응하는 intrinsic/extrinsic/정규화, 평가 무작위 30뷰 camera-set의 실제 제공 여부 미확인. 코드로 새로 만든 카메라를 제공된 공식 GT라고 부르지 않음 |
| 외관 GT용 texture | PhysX README는 별도 ShapeNetCore 사용을 안내 | PartNet 부품만으로 textured RGB GT가 확보됐다고 할 수 없음. object/part/texture 경로·좌표 연결과 접근 권한 확인 필요 |

README의 `103`, `502`는 디렉터리 예시이며, Folding Knife annotation 예시와 ID가 연결되지 않는다. 이를 곧바로 공식 test의 관절 표본으로 지정하지 않았다. category 이름이나 기존 table 생성 예제만 보고 고정 물체라고 분류하지도 않았다.

## 2. 부분 다운로드와 예상 용량

| 확보 경로 | 확인 결과 | 예상 전송량·디스크 |
|---|---|---|
| 기본 `PhysXNet.zip` 전체를 받고 필요한 객체만 해제 | 기존 공식 배포로 확인된 파일 단위 경로. 아직 실행하지 않음 | **16,306,354,206 bytes = 16.31 GB / 15.19 GiB** 전송. 압축파일 보관 외에 선택 파일 해제·임시 공간이 추가됨. 해제 크기는 미확인 |
| HF `allow_patterns`/파일명으로 기본판의 특정 object만 선택 | 현재 확인한 기본판 배포는 ZIP 한 파일. HF의 필터는 저장소 파일 선택이므로 ZIP 내부 `finaljson/<id>.json` 등을 선택하는 기능으로 사용할 수 없음 | ZIP을 선택하면 전체 파일 크기 기준. `*.json` 필터만으로 내부 annotation이 내려오는 것이 아님 |
| ZIP 중앙목록 + HTTP Range로 필요한 멤버만 받기 | 기술적 후보이며 이 서버/파일에 대한 성공 검증 없음. Range 응답·ZIP/ZIP64 구조·압축 방식·멤버 offset/크기·무결성 확인 필요 | 중앙목록과 필요한 멤버의 압축 크기를 알아야 산정 가능. **2개 표본의 MB 단위 추정값을 제시할 근거 없음**. 이번에는 중앙목록 바이트도 받지 않음 |
| 저자가 제공하는 object별 묶음/annotation index | 조회한 기본판 저장소 파일 목록에서 별도 제공을 확인하지 못함 | 제공된다면 해당 파일들의 합계로 산정. 현재 파일 경로/크기 미확정. 저자에게 메시지를 보내지는 않음 |
| 별도 ShapeNetCore texture | 공식 연결 출처는 category ZIP과 접근 승인 안내를 제공 | 선택 객체의 category·실제 texture 경로가 정해져야 용량 산정 가능. 기본 ZIP의 16.31 GB에 포함됐다고 가정하지 않음 |

파일 단위 다운로드/필터의 근거는 [HF 공식 다운로드 문서](https://huggingface.co/docs/huggingface_hub/guides/download#filter-files-to-download)다. ZIP 내부 선택 불가 판단은 이 파일 단위 API와 현재 배포 구조를 결합한 해석이다. HTTP Range 경로는 미검증이므로 사용할 수 있다고 확정하지 않는다. 향후 부분 조회가 실패해도 전체 16.31 GB 다운로드로 자동 전환해서는 안 된다.

`PhysXNet.zip`의 기존 LFS SHA256은 `a4970a3936e8a1fc823d17b64d23b167d73997a13686011bc46f7b98774a7e75`이다. 배포 metadata 값이며 다운로드 검증값이 아니다. 부분 파일만 받는다면 이 archive 전체 hash를 검증했다고 보고할 수 없다. 선택 파일의 hash·archive revision·추출 위치/방식과 archive 전체 검증 여부를 별도로 기록해야 한다.

[ShapeNetCore 공개 페이지](https://huggingface.co/datasets/ShapeNet/ShapeNetCore/tree/main)는 접근 승인이 필요한 자료라고 안내한다. 사용자 계정의 승인 여부는 조회하지 않았으며 선배의 인증정보도 사용하지 않았다. PhysXNet-XL의 작은 archive나 다른 물체를 기본판 test GT의 대체물로 선정하지 않았다.

## 3. 고정·관절 최소 표본 선정 순서 — 제안, 미실행

1. 원본 test 1,000행과 중복을 유지한 상태에서 **실제 annotation 또는 공식 object 분류 인덱스**를 먼저 확인한다. 현재는 종류를 보증하는 ID 쌍이 없다.
2. 진단용으로 고정 물체 1개와 관절 물체 1개를 선택한다. 고정 후보는 이동 관절이 없음을 annotation에서 확인하고, 관절 후보는 유효한 parent-child·축·범위가 있는 B/C 등의 관절을 확인한다. 구체적 선정/제외 기준은 제안이며 논문 평가 split이나 가중치를 변경하는 결정이 아니다.
3. 각 ID에서 annotation 1개, 모든 부품 OBJ/참조 파일, 공식 선택 기준에 대응하는 입력 이미지, 설명 필드와 질문 선택 근거, 입력/평가 카메라 자료를 짝지어 존재·크기를 확인한다. 외관까지 연결할 경우 texture 자료를 추가한다.
4. 부족한 질문표·카메라·맵을 임의 생성해 공식 제공 GT로 채우지 않는다. 미확정 binding은 그대로 차단하고, 확보 경로·정확한 파일 합계가 정해진 뒤 별도 다운로드 단계로 넘어간다. 이번에는 그 단계로 진행하지 않았다.

향후 저장 후보는 `/home/minsujo/Desktop/SH/PHYSx/data/physxnet-minimal/`이며, 다운로드 cache/temp/log도 기존 PHYSx 경계를 따른다. 이번에는 해당 데이터 폴더나 실행 스크립트를 만들지 않았다.

## 4. 로컬 경로 대조에서 추가 확인한 차단 사항

기존 `sources/physx-4f54e750a309/dataset_toolkits/finalindex.json`과 원래 CSV를 표준 라이브러리로 읽어 문자열 ID 포함 여부만 대조했다. **test 1,000행 중 960행(고유 ID 933개)에 경로가 있고, 40행(고유 ID 39개)은 없다.** 이는 texture 실물 존재/정확성 검증이나 40행의 평가 제외 결정이 아니다.

예를 들어 첫 test 행의 ID `7271`은 이 맵에 없고, 다음 `29354`, `21356`에는 경로가 있다. 어느 것도 고정/관절로 확정하지 않았다. 따라서 앞쪽 ID를 무조건 최소 표본으로 고르는 방식도 현재는 적절하지 않다. 원본 CSV·manifest·매핑 JSON을 수정하지 않았다.

최종 차단 사항은 **(1) archive 내부 파일목록·부분 접근·표본 용량, (2) 실제 annotation에 의한 고정/관절 test ID 구분, (3) 공식 질문/입력 뷰/카메라 대응, (4) texture 매핑·접근 권한**이다. 이번 조사 성공 범위는 확보 경로와 미확인 조건의 정리이며, GT 확보/연결 성공이 아니다.
