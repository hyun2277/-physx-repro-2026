## PNG 내부 확인과 역할 판단

- 12개 PNG 모두 실제로 열어 PNG signature/format, 400×400, RGB를 확인했으며 PIL이 보고한 text/EXIF/info metadata는 비어 있었다. 파일명은 part index+name 형태다.
- 직접 확인되는 사실은 `version_1/partseg/<id>/imgs/` 아래에 부품명과 대응하는 PNG가 있다는 것뿐이다. 이 구조는 part annotation/part preview 계열이라는 강한 구조적 단서지만, 파일 자체에 conditioning view ID나 camera 행렬은 없다.
- `example.py`는 `--condpath`(기본 `./example/table.png`)의 외부 이미지를 `Image.open`으로 모델 입력으로 읽는다(공식 코드 140–156행). 최소 추출 PNG를 그 입력으로 선택하는 코드나 매핑은 없다.
- `example_render_gt_foreval.py`는 test 목록→JSON→OBJ를 읽어 GT 시각화를 만들며 `imgs/*.png`를 읽지 않는다(84–92, 112–120, 152–181행). 따라서 이 PNG들이 모델 conditioning input 또는 평가 GT 이미지라고 확정할 직접 코드는 없다.

## 확정 가능 / 추가 자료 필요

### 현재 자료로 확정 가능한 것

- 원본 목록의 test 순서·source index·object ID 대응(0→1000→7271, 1→1001→29354)과 목록 SHA256.
- 각 후보의 JSON, 6개 OBJ, 6개 PNG가 archive member 경로와 object ID로 묶이고, JSON `parts` index와 파일명 stem이 일치한다는 사실.
- JSON의 part label/description/priority/density와 `group_info` 관찰값.
- PNG의 물리 형식·크기·무메타데이터 및 공식 코드가 후보 PNG를 모델 입력/GT 렌더로 직접 읽지 않는다는 정적 사실.

### 추가 원본/검증이 필요한 것

- 공식 평가 conditioning image의 선택 규칙, view ID, 전처리·카메라 hash.
- `renders_cond` 또는 해당 입력의 `transforms.json` 및 공식 평가 camera-set.
- ShapeNet/texture 경로와 각 OBJ의 재질 정합.
- 렌더된 숫자 GT maps, mask, channel 단위와 JSON/OBJ→map 대응. JSON의 annotation이 곧 metric-ready GT라는 가정은 금지한다.
- 관절 pose/joint graph 전체와 fixed/single/multiple joint 공식 분류.
