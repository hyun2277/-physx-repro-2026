## 두 표본 연결 판정

현재 자료만으로 `7271`·`29354`의 conditioning image와 camera/transforms를 실제 연결할 수 **없다**.

- 확인 가능: test ID→archive JSON/OBJ/part PNG, JSON part index→파일 stem, 공식 코드가 기대하는 파생 경로와 카메라 metadata 형식.
- 확인 불가: 어떤 PNG가 inference conditioning input인지, 그 PNG의 view ID·카메라 행렬·전처리, `renders_cond`와 후보의 instance ID, 평가 GT 렌더 map과 mask.
- `29354`의 `finalindex.json` ShapeNet 문자열은 추가 원본을 찾기 위한 후보 경로일 뿐이다. `7271`은 현재 매핑 JSON에 항목이 없어 별도 원본 mapping이 필요하다.
- ZIP의 `camera.png` 한 건은 part label 파일명이며 camera metadata의 증거가 아니다.

## 다음에 필요한 최소 외부 자료와 용량 판단

공식 PhysX-3D preprocessing 결과 또는 동일한 upstream 원본에서 다음을 **표본별로만** 확보해야 한다.

1. `metadata.csv`의 7271/29354 instance 행과 `local_path`/instance ID: `render_cond.py`가 어느 mesh를 읽는지 확인하기 위해 필요하다. 현재 파일은 작업 폴더에 없다.
2. 각 instance의 원본 mesh와 texture 연결 자료. 29354는 `ShapeNet/04379243/db406d9b2a94bce5622d7484764b58f`가 후보 경로이고, 7271은 mapping이 먼저 필요하다. 실제 파일·크기는 원격 원본 목록 확인 전 알 수 없다.
3. 표본별 `renders_cond/<instance>/transforms.json`과 선택된 PNG(최소 한 view 또는 논문 평가가 요구하는 camera-set 전체): conditioning image와 camera를 함께 검증하기 위해 필요하다.
4. 평가용 렌더 GT map·mask·channel/unit 메타데이터: JSON/OBJ가 metric-ready GT인지 확인하기 위해 필요하다.

공식 소스에는 이 파일들의 표본별 크기 목록이나 archive hash가 없으므로 예상 용량을 숫자로 단정할 근거가 없다. 코드 기본값으로 생성되는 경우에도 conditioning은 최대 24 PNG(1024px)+`transforms.json`, ordinary render는 최대 150 PNG(512px)+`transforms.json`이라는 **파일 수/해상도 설정만** 확인된다. 실제 압축 크기는 mesh·PNG 압축·texture에 따라 달라진다. 전체 ShapeNet/PartNet 다운로드를 필요한 최소 자료라고 간주하지 않는다.

## 평가 조건 주의

`example_render_gt_foreval.py`의 `render_video_gt(..., num_frames=30)`은 예제 시각화용 30프레임 orbit이다. 논문 외관 PSNR의 단위구 무작위 30시점 camera-set과 같은 조건으로 사용하지 않는다.

다음 우선순위는 (1) 표본별 공식 preprocessing `metadata.csv`/instance 매핑 확인, (2) `renders_cond`의 transforms와 PNG의 실제 hash·view 대응 확인, (3) 평가 GT map·mask·단위 확인이다. 이 세 항목 전에는 metric-ready binding이나 전체 평가를 시작하지 않는다.
