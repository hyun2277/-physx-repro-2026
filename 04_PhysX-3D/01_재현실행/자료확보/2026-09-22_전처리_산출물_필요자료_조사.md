# 2026-09-22 PhysXNet 전처리 산출물과 필요 원본 조사

## 범위

고정 upstream 소스의 `precess.sh`, `merge_property.py`, `gen_csv.py`, `retrieval_texture_example.py`, `build_metadata.py`를 실행하지 않고 순서와 파일 참조만 추적했다. 현재 `PhysXNet.zip`의 JSON·OBJ·PNG만 사용 가능한지 구분했으며, 새 다운로드·압축 해제·모델/GPU 실행·원본 수정은 하지 않았다.

## 단계별 입력·출력·외부 의존성

| 순서 | 스크립트 | 읽는 입력 | 만드는 출력 | 외부 의존성/제약 |
|---:|---|---|---|---|
| 1 | `merge_property.py --datapath ./physxnet` | `finaljson/<id>.json`, `partseg/<id>/objs/*.obj`, JSON의 `parts`·`group_info`·설명 문자열 | `phy_dataset/<id>/model.obj`, `clip.npy`, `clip_ind_new.npy`, `otherproperty.npy`, 로그 | PyTorch, trimesh, CLIP `ViT-L/14` 모델. 코드가 `clip.load`를 호출하며 text embedding을 계산한다. ZIP의 part PNG는 읽지 않는다. |
| 2 | `gen_csv.py` | `phy_dataset/*/model_tex.obj` 경로를 전제로 한 디렉터리 목록 | `../datasets/PhysXNet/metadata.csv`, `merged_records/1743666055_downloaded_0.csv` | `model_tex.obj`가 아직 없으면 경로만 기록되고 파일은 유효하지 않다. `sha256` 열은 디렉터리 이름에 `_`를 붙인 처리용 ID다. |
| 3 | `retrieval_texture_example.py` | `phy_dataset/<id>/model.obj`, `finalindex.json`, ShapeNet mapped `models/model_normalized.obj` | `phy_dataset/<id>/model_tex.obj`, texture/UV가 포함된 OBJ, 로그 | ShapeNet 원본과 mapping이 필요하다. mapping이 없으면 회색 1×1 texture로 `model_tex.obj`를 만들지만 공식 texture 복원 결과가 아니다. |
| 4 | `build_metadata.py PhysXNet --output_dir ../datasets/PhysXNet` | 기존 `metadata.csv` 또는 `PhysXNet.py.get_metadata()`의 CSV, `downloaded_*.csv`, 이후 `rendered_*.csv`·`cond_rendered_*.csv` 등 | 갱신 `metadata.csv`, `statistics.txt`, `merged_records` 이동본, 상태 열 | `metadata.csv`가 없으면 `datasets/PhysXNet/metadata.csv`를 읽으려 하며, `PhysXNet.py`는 그 파일을 전제로 한다. 파생 CSV가 없으면 상태는 기본 false/0으로 남는다. |
| 5 | `render.py PhysXNet` | `metadata.csv.local_path`의 `model_tex.obj`, Blender | `renders/<instance>/*.png`, `transforms.json`, `rendered_*.csv` | Blender 3.0.1, mesh/texture, 렌더 환경. 기본 150 views·512px이며 NumPy random offset을 사용한다. |
| 6 | `build_metadata.py` 재실행 | `rendered_*.csv` 및 파일 존재 | `metadata.csv`의 `rendered` 등 갱신 | 렌더 산출물이 실제로 있어야 true가 된다. |
| 7 | `render_cond.py PhysXNet` | `metadata.csv`, 선택된 `local_path`, instance/sha256 | `renders_cond/<instance>/*.png`, `transforms.json`, `cond_rendered_*.csv` | Blender 3.0.1, mesh/texture. 기본 24 views·1024px, seed 없는 random offset/radius/FOV. |
| 8 | `build_metadata.py` 재실행 | `cond_rendered_*.csv` 또는 `renders_cond/.../transforms.json` | `metadata.csv`의 `cond_rendered` 갱신 | conditioning image가 이미 생성돼 있어야 한다. |

`precess.sh`는 이후 voxel/feature/latent 단계도 호출한다. 이 조사에서 평가 입력과 직접 관련된 단계는 위 1–8이며, 어느 단계도 논문의 test camera-set을 제공한다고 선언하지 않는다.

## 현재 ZIP만으로 가능한 것

ZIP에서 직접 확인된 것은 `version_1/finaljson/*.json`, `partseg/*/objs/*.obj`, `partseg/*/imgs/*.png`이다.

| 산출물 | ZIP만으로 가능한가 | 이유 |
|---|---|---|
| JSON→part OBJ 순서 확인 | 가능 | `merge_property.py`가 요구하는 JSON/OBJ가 있고 최소 표본에서 index/stem을 대조했다. |
| `merge_property.py`의 `model.obj`·property arrays | 파일 변환 자체는 가능 | JSON·OBJ와 CLIP 외 text model만 있으면 된다. 실제 실행/출력은 이번 범위가 아니다. ZIP PNG는 사용하지 않는다. |
| `metadata.csv`의 행 형식/경로 문자열 | 부분 가능 | `gen_csv.py`는 `phy_dataset` 디렉터리와 `model_tex.obj` 이름만 사용한다. texture 완료 여부와 무관하게 행을 쓸 수 있지만 경로가 실제 파일을 가리킨다는 보장은 없다. |
| 공식 texture `model_tex.obj` | 불가 | ShapeNet mapped mesh가 필요하다. `finalindex.json` 및 원본이 ZIP에 없다. |
| `renders`/`renders_cond` PNG와 `transforms.json` | 원칙상 렌더 가능하지만 이번 ZIP만으로는 불완전 | `model_tex.obj`, Blender, 파생 metadata가 필요하다. ZIP에는 camera metadata나 render 결과가 없다. |
| metric-ready GT map/mask/camera-set | 불가 | 전처리 스크립트는 학습/렌더 산출물을 만들 뿐 논문 평가 GT 대응·분모·camera-set을 제공하지 않는다. |

## 7271·29354 최소 연결

| 항목 | 7271 | 29354 |
|---|---|---|
| ZIP 원료 | `finaljson/7271.json`, `partseg/7271/objs/0..5.obj`, `imgs/*.png` | 동일 경로의 `29354` |
| `merge_property.py` 결과 | `phy_dataset/7271/model.obj` 및 arrays가 필요 | `phy_dataset/29354/model.obj` 및 arrays가 필요 |
| `metadata.csv` 행 | `sha256=7271_`, `local_path=phy_dataset/7271/model_tex.obj` 문자열이 `gen_csv.py` 형식. 실제 file은 아직 없음 | `sha256=29354_`, `local_path=phy_dataset/29354/model_tex.obj` 문자열. 실제 file은 아직 없음 |
| instance ID | 코드상 `phy_dataset` 디렉터리명과 `sha256` 열의 `7271_`/`29354_`; 공식 cryptographic hash 아님 | 동일 |
| texture retrieval | `finalindex.json`에 7271 key가 없어 ShapeNet source 식별자부터 미확정 | `shapenet/04379243/db406d9b2a94bce5622d7484764b58f/models/model_normalized.obj` 후보 mapping이 로컬 JSON에 있음; remote 파일 존재는 미확인 |
| `model_tex.obj` | ShapeNet mapping + source mesh/texture 필요 | 위 mapped ShapeNet 원본 + OBJ texture/UV 필요 |
| `renders_cond`/`transforms.json` | `metadata.csv.local_path`가 가리키는 실제 mesh, Blender, random camera generation 필요 | 동일 |

`imgs/*.png`는 이 다섯 전처리 스크립트에서 읽히지 않는다. 따라서 part PNG를 conditioning input이나 camera view로 재사용할 근거가 없다.

## PartNet·ShapeNet 공식 접근과 라이선스

upstream README는 [PartNet archive](https://huggingface.co/datasets/ShapeNet/PartNet-archive)와 [ShapeNetCore](https://huggingface.co/datasets/ShapeNet/ShapeNetCore)를 별도 자료로 가리킨다. 공식 페이지를 읽기 전용으로 확인한 결과:

| 자료 | 공식 페이지에서 확인한 내용 | 이번 표본 파일 상태 |
|---|---|---|
| PartNet-archive | `License: other`; 로그인 후 조건 동의와 full name/PI/affiliation 입력, access approval 필요. non-commercial research/education 조건. 페이지가 archive 총 138 GB와 chunk 파일(302 MB + 10 GB chunks 등)을 공개한다. | 7271/29354에 해당하는 PartNet 파일명·부분 파일 크기는 확인하지 않았다. archive 전체 크기를 표본 용량으로 사용하지 않는다. |
| ShapeNetCore | `License: other`; 동일한 게이트와 access approval, non-commercial research/education 조건. v2 약 51,300 models, 페이지 총 24 GB. | 29354의 mapping 문자열은 있으나 해당 파일 접근/존재·크기는 확인하지 않았다. 7271 mapping은 없다. |

공식 페이지가 공개한 총량은 dataset-level 표시이며 특정 표본의 파일 크기나 부분 다운로드 가능성을 의미하지 않는다. 이번 조사에서는 gated 원본에 접근하거나 파일을 다운로드하지 않았다.

## 논문 평가와 분리해야 할 항목

- `render_cond.py`의 기본 24-view conditioning render는 학습 preprocessing 경로다. 논문 test 입력 이미지·camera-set과 같다고 말할 수 없다.
- `render.py`의 기본 150-view/512px과 `render_cond.py`의 24-view/1024px는 서로 다른 파생 자료다.
- 공식 GT 예제의 30-frame orbit은 논문 외관 PSNR의 무작위 단위구 30시점과 동일하지 않다.
- `metadata.csv`의 `cond_rendered=true`는 파일 존재 상태만 표시하며, 논문 평가 입력·camera convention·전처리 hash의 증거가 아니다.
- texture retrieval이 완료돼도 metric-ready GT map, mask, 질문/part/view 대응과 최종 평가 분모는 별도로 확정해야 한다.

## 현재 가능한 재현 범위와 다음 검산

현재는 ZIP 구조와 JSON↔OBJ↔PNG, 전처리의 파일 경로·상태 열·카메라 생성 규칙을 정적 검산할 수 있다. 외부 자료를 승인된 방식으로 표본별 확보한 뒤에는 두 ID에 대해 `metadata.csv` 행→`local_path`→`model_tex.obj`→`renders_cond`/`transforms.json`의 파일 hash와 camera metadata를 CPU에서 소표본 검산할 수 있다. 그 결과도 논문 전체 test나 논문 동일 camera-set을 입증하지 않는다.
