## 2. PC 환경 재현 가능성 — **PhysGaussian(ficus)은 확정, Spring-Gaus(torus/burger)는 아직 미실행**

`02_PC환경_재현가능성_검토.md`는 PhysGaussian·Spring-Gaus 둘 다에 대해 "VRAM이 부족할지는 실행 전까지 단정 불가"라고 신중하게 표시해뒀는데, 저희가 지금까지 **PhysGaussian만 실제로 끝까지 돌려서 확정**한 상태입니다. Spring-Gaus는 아직 저희도 실행 전이라 그 부분의 "추정"은 여전히 미확정입니다 — 오해 없으시게 구분해서 말씀드립니다.

**PhysGaussian(ficus) 기준 — 확인됨:**
- Compute Capability 7.5 문제없음 — **확인됨**
- CUDA 11.8/PyTorch 2.0.0 재빌드 불필요 — **확인됨**
- VRAM 11GB로 충분한지 — **확인됨.** ficus 데모(17만 개 파티클) 기준 OOM 없이 끝까지 완주(125프레임, 총 1분 28초 소요)

**Spring-Gaus(torus/burger) — 아직 미확정 (저희도 다음 단계로 진행 예정):**
- Compute Capability·CUDA 버전 자체는 PhysGaussian과 같은 판단 근거(Turing sm_75, CUDA 11.6 정식 지원)로 문제없을 것으로 보이나, VRAM은 `02_PC환경_재현가능성_검토.md`가 이미 정확히 짚었듯 **실제 학습(`train.py`)을 돌려봐야 확답 가능**합니다. 저희도 아직 실행 전입니다.

## 3. 재현 실행 절차 — 그대로 따라가되, **추가로 필요했던 조치 3가지**를 꼭 알려드리고 싶습니다 (중요)

`03_재현_실행_절차.md`의 명령어 자체는 정확했고 그대로 따라갔습니다. 다만 저희 환경(최신 winget으로 설치한 Visual Studio Build Tools 2022, 버전 17.14/MSVC 14.44)에서는 **`diff-gaussian-rasterization` 컴파일이 그대로는 실패**했고, 원인을 찾아 아래 3가지 조치를 적용해서 해결했습니다(이후 `simple-knn`에는 처음부터 이 조치를 반영해서 한 번에 성공했습니다). **팀원분 PC도 저희와 똑같이 RTX 2080 Ti이고 아마 최신 VS Build Tools를 쓰실 가능성이 높아서, 미리 알려드립니다.**

1. **`pip install`에 `--no-build-isolation` 옵션 추가 필요**
   - 원인: pip이 만드는 빌드 격리 환경에 이미 설치된 torch가 안 보여서 `ModuleNotFoundError: No module named 'torch'` 발생

2. **setup.py의 `extra_compile_args`에 nvcc 플래그 2개 추가 필요**: `-allow-unsupported-compiler`, `-D_ALLOW_COMPILER_AND_STL_VERSION_MISMATCH`
   - 원인: **CUDA 11.8(2022년)이 최신 MSVC(14.44, VS 2022 17.14)를 "지원 안 함"으로 판단**해서 컴파일 자체를 거부함(`fatal error C1189`). 반대로 최신 MSVC의 표준 라이브러리도 "이렇게 오래된 CUDA는 안 맞다"고 판단해서 또 막음(`error STL1002`). 둘 다 NVIDIA/Microsoft가 공식 제공하는 우회 플래그로 해결됨 — 실제 컴파일 결과에 문제는 없었습니다(정상 동작 확인).
   - 즉 **CUDA 11.8 자체는 문제없는데, VS Build Tools가 너무 최신 버전이라 생기는 충돌**입니다.

3. **`simple-knn` 폴더에 `__init__.py`가 원래 없어서 직접 추가해야 함**
   - 이건 저희 환경 문제가 아니라 **원본 저장소 자체의 누락**입니다. 컴파일은 성공하는데 `import simple_knn`이 안 되는 경우, `submodules/simple-knn/simple_knn/` 폴더에 빈 `__init__.py` 파일 하나만 만들어주면 해결됩니다.

이 3가지를 반영한 실제 수정 파일 3개를 같은 폴더의 `수정된_setup_파일들/`에 그대로 첨부해뒀습니다 — 원래 파일과 이름만 바꿔서 넣어드렸으니, 각자 위치에 덮어써서 그대로 쓰시면 됩니다:
- `diff-gaussian-rasterization_setup.py` → `.../submodules/diff-gaussian-rasterization/setup.py`로
- `simple-knn_setup.py` → `.../submodules/simple-knn/setup.py`로
- `simple_knn___init__.py` → `.../submodules/simple-knn/simple_knn/__init__.py`로 (빈 파일)

## 실제 실행 결과 (참고용)

- `python gs_simulation.py --model_path ./model/ficus_whitebg-trained/ --output_path output --config ./config/ficus_config.json --render_img --compile_video --white_bg` 명령을 그대로 실행
- 125프레임 전부 정상 렌더링(총 1분 28초), ficus 화분이 물리적으로 흔들리는 결과 이미지 생성 확인(렌더링된 이미지를 직접 열어봐서 화분 형태가 정상적으로 나온 것까지 눈으로 확인)
- `--compile_video` 옵션 자체는 `ffmpeg`이 시스템에 없어서 그 자리에서는 실패했으나, 이후 `ffmpeg`을 별도 설치해서 동일한 프레임들로 직접 영상화까지 완료했습니다 — 최종 `output.mp4`(125프레임, 25fps, 약 5초 분량) 생성 확인.

**결론**: PhysGaussian(1번) 재현은 저희 환경에서 시뮬레이션 계산부터 최종 영상 생성까지 전부 성공했습니다. 위 3가지 조치만 미리 아시면 팀원분 PC(RTX 2080 Ti)에서도 동일하게 될 것으로 예상합니다.
