# Spring-Gaus 재현 결과 (김승민) — torus 재현 미완료, 원인 분석 결과

**작성일**: 2026-09-14
**실행 환경**: NVIDIA RTX 2080 Ti(11GB), Intel i7-9700K, RAM 64GB, Windows
**자료 출처**: 김승민 팀원이 작성한 재현 기록 문서 4건을 바탕으로 정리했습니다.

torus(합성 데이터)를 네 차례(RUN 1·RUN 2·RUN 3·스모크 테스트) 시도했지만 아직 재현을 완료하지 못했습니다.
물리 시뮬레이션의 세부 계산 단계(서브스텝) 수가 200으로 늘어나는 학습 후반부에서 프레임 하나 처리에
최대 1시간 가까이 걸리는 지연이 반복적으로 발생했기 때문입니다. 이를 그냥 넘기지 않고 `torch.profiler`를
이용한 정밀 프로파일링으로 원인을 직접 추적하는 심층 분석을 진행했습니다.

**주요 성과**

- 원본 논문 코드 안에서 실제 성능 저하를 유발하는 결함 2건을 발견했습니다.
  1. 물리 계산 루프 안에서 불필요하게 반복 호출되는 GPU 메모리 정리 함수
  2. 특정 경계조건 계산의 역전파 연산이 비정상적으로 느려지는 문제
- 두 결함 모두 공식 문서 검토와 수치 동등성 검증(수정 전후 계산 결과가 소수점 5자리까지 동일함을 확인)을
  거쳐, "계산 결과에는 영향을 주지 않는 정당한 성능 개선"임을 검증했습니다.
- 격리된 벤치마크 환경에서는 해당 구간 처리 시간을 최대 **32.6배** 단축시키는 성과를 확인했습니다.

다만 이 수정들을 실제 학습 전체에 적용했을 때는 지연 현상이 완전히 해소되지는 않아, torus 데모는 아직
끝까지 완료하지 못한 상태이며 burger(실측 데이터) 재현은 이어서 진행할 예정입니다. 이수현과 동일한 사양
(RTX 2080 Ti 11GB 등)의 PC임에도 학습 속도에 차이가 있는 부분은, 이후 원본 로그·`nvidia-smi` 실측
자료까지 받아 이수현 쪽과 정밀 대조한 결과(자세한 내용은 같은 폴더의 `결과비교_및_원인분석.md` 참고) **GPU
드라이버 버전 차이(572.83 vs 576.02)만 유일하게 원인 가능성을 배제하지 못했고**, 이로 인한 미세한
부동소수점 차이가 물리 시뮬레이션의 경계조건(바닥 접촉) 판정을 갈라놓았을 가능성이 가장 유력한
가설로 남아 있습니다(직접 증명은 못 함). 다음 재현 시에는 (a) VRAM 여유 부족이 실제 원인인지 직접
검증하거나 (b) VRAM이 더 넉넉한 GPU 환경에서 같은 실험을 재현해 VRAM 여유를 늘리면 문제가 사라지는지
확인하는 방향으로 다시 시도해볼 계획입니다. 다만 이수현도 같은 RTX 2080 Ti 11GB로 이미 성공했기
때문에, "11GB 카드 자체의 한계"라기보다는 이 PC·환경에 국한된 문제일 가능성이 있어 — (b)는 원인을
밝히는 검증이라기보다 더 넉넉한 환경으로 우회해서 완주를 시도해보는 성격에 가깝습니다.
