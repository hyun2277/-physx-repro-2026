# Spring-Gaus 재현 결과 (김승민) — torus 최종 성공(7회 시도 중 3회), 원인은 비결정성으로 잠정 결론

**작성일**: 2026-09-14 (2026-09-15 후속 업데이트 반영)
**실행 환경**: NVIDIA RTX 2080 Ti(11GB), Intel i7-9700K, RAM 64GB, Windows
**자료 출처**: 김승민 팀원이 작성한 재현 기록 문서 4건 + 후속 비교분석 문서(`김승민_torus_실패성공_비교분석.md`,
같은 폴더)를 바탕으로 정리했습니다.

torus(합성 데이터)를 처음 네 차례(RUN 1·RUN 2·RUN 3·스모크 테스트, 2026-09-13 저녁~09-14 아침) 시도했을
때는 재현에 실패했습니다. 물리 시뮬레이션의 세부 계산 단계(서브스텝) 수가 200으로 늘어나는 학습 후반부에서
프레임 하나 처리에 최대 1시간 가까이 걸리는 지연이 반복적으로 발생했기 때문입니다. 이를 그냥 넘기지 않고
`torch.profiler`를 이용한 정밀 프로파일링으로 원인을 직접 추적하는 심층 분석을 진행했습니다.

**이후 같은 날(09-14) 오후~저녁에 이어서 시도한 3회는 모두 성공**했습니다(그중 1회는 300/300 iteration
전체를 56분 29초 만에 완주하고 체크포인트·평가 영상까지 생성). 코드·config·패치 상태·PC·GPU 드라이버가
실패 시도 때와 완전히 동일했음이 `git status`/`git rev-parse`/`nvidia-smi` 직접 대조로 확인되어, 원인은
아래 "이후 원인 분석" 항목에서 다시 설명합니다.

**주요 성과**

- 원본 논문 코드 안에서 실제 성능 저하를 유발하는 결함 2건을 발견했습니다.
  1. 물리 계산 루프 안에서 불필요하게 반복 호출되는 GPU 메모리 정리 함수
  2. 특정 경계조건 계산의 역전파 연산이 비정상적으로 느려지는 문제
- 두 결함 모두 공식 문서 검토와 수치 동등성 검증(수정 전후 계산 결과가 소수점 5자리까지 동일함을 확인)을
  거쳐, "계산 결과에는 영향을 주지 않는 정당한 성능 개선"임을 검증했습니다.
- 격리된 벤치마크 환경에서는 해당 구간 처리 시간을 최대 **32.6배** 단축시키는 성과를 확인했습니다.

다만 이 수정들을 실제 학습 전체에 적용해도 처음 네 차례 시도에서는 지연 현상이 완전히 해소되지 않아
재현에 실패했습니다. 이수현과 동일한 사양(RTX 2080 Ti 11GB 등)의 PC임에도 학습 속도에 차이가 있는 부분은,
당시 원본 로그·`nvidia-smi` 실측 자료까지 받아 이수현 쪽과 정밀 대조한 결과(자세한 내용은 같은 폴더의
`결과비교_및_원인분석.md` 참고) 그 시점에는 **GPU 드라이버 버전 차이(572.83 vs 576.02)만 유일하게 원인
가능성을 배제하지 못한 상태**였습니다.

**이후 원인 분석 (2026-09-15 후속 업데이트)** — 하지만 같은 날 오후~저녁에 같은 PC·같은 드라이버(572.83)·
같은 코드·같은 config로 이어서 시도한 3회가 모두 성공하면서, 위 "GPU 드라이버 차이" 가설은 반박되었습니다.
김승민 PC 한 대 안에서조차 완전히 동일한 조건으로 실패와 성공이 둘 다 나왔기 때문에, 드라이버 차이(이수현
vs 김승민)든 `apply_bc`의 `index_put_` 패치 유무든 성공/실패를 가르는 결정 요인이 아니라는 것이 확인됐습니다
(패치 없는 원본 코드 그대로도 3회 모두 정상 속도로 완주). 즉 문제는 코드·설정·하드웨어·드라이버의 차이가
아니라 **같은 PC·같은 조건에서도 실행 시점에 따라 결과가 갈리는 비결정성 자체**였던 것으로 보이며, 정확한
트리거(재부팅, 백그라운드 프로세스, GPU 열이력 등)는 밝혀지지 않아 "원인 미상"이 현재로서는 가장 정직한
결론입니다. 실용적으로는 torus가 재현 가능함은 확인됐지만(완주 성공 사례·체크포인트·영상 존재), 매 시도
성공을 보장할 수는 없는 상태입니다. 상세 시도별 대조는 같은 폴더의 `김승민_torus_실패성공_비교분석.md`
참고. burger(실측 데이터) 재현은 이어서 진행할 예정입니다.
