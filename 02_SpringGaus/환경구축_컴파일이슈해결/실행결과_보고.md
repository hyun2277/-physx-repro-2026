# Spring-Gaus 환경 구축 및 컴파일 이슈 해결

PhysGaussian과 렌더러 핵심 코드(diff-gaussian-rasterization·simple-knn)는 동일하지만, Spring-Gaus는
Python 3.7 + PyTorch 1.13.1(CUDA 11.6) 환경을 요구하고 pytorch3d까지 추가로 필요해, PhysGaussian에서는
겪지 않았던 문제들이 추가로 발생했습니다. 실행 환경: i7-9700K/64GB/RTX 2080 Ti, Windows.

## 1. PhysGaussian과 동일하게 재적용한 것

- `pip install --no-build-isolation` (빌드 격리 환경이 기존 torch를 못 찾는 문제)
- nvcc 플래그 `-allow-unsupported-compiler -D_ALLOW_COMPILER_AND_STL_VERSION_MISMATCH` (CUDA와 최신
  MSVC 간 버전 충돌 우회)
- `simple-knn/simple_knn/__init__.py` 빈 파일 추가(원본 저장소 누락)

## 2. Spring-Gaus에서 새로 겪은 문제 3가지

### ① pybind11 템플릿 오류 — PyTorch 1.13.1 특유 문제
- **증상**: `error: too few arguments for template template parameter "Tuple"` — PyTorch(2.0.0)가
  아니라 **PyTorch 1.13.1이 내장한 pybind11 헤더**가 최신 MSVC(14.44)의 더 엄격해진 템플릿 규칙과
  충돌해서 발생. PhysGaussian(PyTorch 2.0.0)에서는 겪지 않았던, Spring-Gaus만의 문제.
- **원인 조사**: 동일 저장소(`graphdeco-inria/gaussian-splatting`)의 GitHub 이슈에서 같은 문제와
  커뮤니티 검증된 해결법을 확인.
- **해결**: 설치된 PyTorch가 내장한 `torch/include/pybind11/cast.h`에서, `tuple_caster` 전방 선언과
  `type_caster<std::pair<T1,T2>>`/`type_caster<std::tuple<Ts...>>` 특수화를 `tuple_caster` 클래스
  본문보다 **앞으로** 옮김(저장소 코드가 아니라 PyTorch 패키지 자체의 헤더 파일을 수정 — Spring-Gaus
  소스 코드는 무수정).

### ② pytorch3d 빌드 실패 — C++ 표준 플래그 문제
- **증상**: `error C2039: 'optional': 'std'는 멤버가 아닙니다` — `setup.py`의 C++ 표준 플래그가
  Unix 스타일(`-std=c++17`)로 적혀 있어 Windows(MSVC)에서는 무시되고, PyTorch의 빌드 도구가 조용히
  `/std:c++14`로 낮춰버려 `std::optional`을 못 씀.
- **해결**: `pytorch3d/setup.py`를 OS에 따라 분기하도록 수정.
  ```diff
  - extra_compile_args = {"cxx": ["-std=c++17"]}
  + extra_compile_args = {"cxx": ["/std:c++17" if os.name == "nt" else "-std=c++17"]}
  ```

### ③ burger(실측 데이터) 로드 실패 — 원본 코드의 Windows 경로 버그
- **증상**: `FileNotFoundError` — burger(실측 카메라 데이터) 학습 시작 직후 마스크 파일을 못 찾음.
- **원인**: `lib/datasets/real_capture.py`가 이미지 경로에서 마스크 경로를 만들 때
  `image_path.replace('/images/', '/masks/')`처럼 **유닉스 스타일 슬래시 문자열 치환**을 사용 —
  Windows의 역슬래시 경로에서는 이 치환이 그냥 아무 효과 없이 실패함(원저자가 Linux에서 개발한 것으로
  추정, 저희 환경 문제가 아니라 원본 저장소 자체의 결함).
- **해결**: `os.path.join` 기반으로 마스크 경로를 직접 조립하도록 수정(계산 로직 변경 없음, 경로 조립
  방식만 Windows 호환으로 교체).
  ```diff
  - mask_path = image_path.replace('.JPG', '.png').replace('/images/', '/masks/')
  + mask_path = os.path.join(self.static_dir, 'masks', self.obj_name, im.name.replace('.JPG', '.png'))
  ```

## 결론

Spring-Gaus는 PhysGaussian과 렌더러 코어를 공유하지만, 서로 다른 Python/PyTorch 버전 요구사항과
pytorch3d 의존성, 그리고 원본 저장소의 Windows 비호환 코드 때문에 **PhysGaussian보다 더 많은 환경
문제를 추가로 해결해야 했습니다.** 이 문제들을 해결한 뒤 torus·burger 재현을 진행했습니다(결과는
`결과영상/` 폴더 및 각자 결과 요약 문서 참고).
