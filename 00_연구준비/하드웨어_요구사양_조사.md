**조사 방법**: 각 논문의 arXiv 원문(Implementation Details/Experiments 섹션, ar5iv HTML 렌더링으로 직접 확인) + 공식 GitHub README를 직접 대조. 원문에 없는 내용은 "명시 없음"으로 표기하고 추정하지 않았습니다. 이 문서 아래쪽의 GPU 모델(RTX 5090/2080) 관련 사실은 PyTorch 공식 GitHub 이슈, NVIDIA 개발자 포럼, 3D Gaussian Splatting 공식 저장소 이슈를 근거로 했습니다.

## 2. 공통 기반 — 6편이 공유하는 렌더러의 공식 요구사항

PhysGaussian·Spring-Gaus·GaussianProperty·GASP·PhysDreamer·Physics3D는 모두 원본 3D Gaussian Splatting(`graphdeco-inria/gaussian-splatting`) 렌더러(`diff-gaussian-rasterization`)를 기반으로 합니다. 이 공식 저장소 README의 **Hardware Requirements** 섹션 원문:

> "CUDA-ready GPU with Compute Capability **7.0+**" · "**24 GB VRAM** (to train to paper evaluation quality)" · "CUDA SDK **11.8** 권장(11.6은 이슈 있음)"

FAQ에는 VRAM이 부족하면 densification 관련 파라미터를 낮춰 더 적은 VRAM으로도 학습 가능하지만, 결과 품질(디테일)이 떨어진다고 명시되어 있습니다.

## 3. "최대 쓸 수 있는 컴퓨터가 RTX 5090이면?" — 조사 결과

**RTX 5090 스펙**: Blackwell 아키텍처, **Compute Capability sm_120(12.0)**, 32GB GDDR7 (NVIDIA 공식 스펙 교차확인)

**핵심 문제 — VRAM이 아니라 "너무 최신이라 오래된 CUDA와 안 맞음"**:
- RTX 5090을 정식 지원하는 최소 조합은 **CUDA 12.8 + PyTorch 2.7.0**입니다. PyTorch 2.7.0이 sm_120 네이티브 지원을 추가한 첫 stable 릴리즈입니다. ([pytorch/pytorch#159207](https://github.com/pytorch/pytorch/issues/159207))
- **CUDA 11.x(11.3/11.6/11.8) 툴킷의 nvcc는 sm_120이라는 아키텍처 자체를 모릅니다.** 즉 논문들이 지정한 버전 그대로는 `diff-gaussian-rasterization` 같은 CUDA 확장 모듈 **컴파일 단계에서 실패**합니다.
- 이미 커뮤니티에서 확인된 해결법: CUDA 12.8+ 설치 후 `TORCH_CUDA_ARCH_LIST="12.0"` 지정, 소스에서 재컴파일. ([graphdeco-inria/gaussian-splatting#1313](https://github.com/graphdeco-inria/gaussian-splatting/issues/1313), [nerfstudio-project/gsplat#855](https://github.com/nerfstudio-project/gsplat/issues/855))
- **Spring-Gaus는 추가 문제**: README가 지정한 Python 3.7 자체가 PyTorch 2.7+가 지원하지 않는 EOL 버전이라, CUDA 문제와 별개로 Python 버전도 올려야 하고 기존에 지적된 pytorch3d 빌드 이슈가 커질 수 있습니다.
- URDFormer(torch 1.12.1+cu113)도 동일하게 그대로는 5090에서 실행 불가 — 전체 환경을 새로 맞춰야 함.

**VRAM 측면**: 32GB는 10편 중 어떤 논문이 명시한 수치(최대 A6000 48GB)보다도 넉넉하지는 않지만, 실제 계산량 자체가 크지 않은 논문들이라 32GB로 부족할 가능성은 낮습니다(다만 A6000 48GB를 "왜" 썼는지 논문에 이유가 없어 이 판단은 추정입니다).

**결론**: 5090은 성능·용량은 충분하지만, 오래된 논문 코드 특성상 README를 그대로 따라 하면 실패합니다. CUDA 12.8+/PyTorch 2.7+로 맞추고 CUDA 확장 모듈을 직접 재빌드하는 1회성 작업이 필요하며, PhysGaussian에서 이 작업을 한 번 확립하면 같은 렌더러를 쓰는 5편(Spring-Gaus·GaussianProperty·GASP·PhysDreamer·Physics3D)에 재사용 가능할 것으로 판단됩니다.

## 4. "그럼 2080은?" — 조사 결과

**RTX 2080 스펙**: Turing 아키텍처, **Compute Capability sm_75(7.5)**, **8GB GDDR6** (GeForce RTX 2080 기준. RTX 2080 Ti는 11GB, RTX 2080 Super는 8GB — 정확히 어느 모델인지에 따라 VRAM이 다르므로 이 문서에서는 기본형 2080=8GB 기준으로 판단)

**5090과 정반대의 리스크 프로필**:

| | RTX 5090 | RTX 2080 |
|---|---|---|
| Compute Capability | 12.0 (너무 최신) | 7.5 (Turing) |
| 논문들의 CUDA 11.x 툴킷과 컴파일 호환 | ❌ 실패 | ✅ 문제없음 — 3DGS 요구사항(7.0+) 충족, 논문 저자들이 실제 썼던 세대(3090/A40/A6000)와 같은 시기 아키텍처 |
| VRAM | 32GB (충분) | 8GB (공식 권장치 24GB의 1/3) |

**VRAM이 진짜 병목**:
- 8GB 미만 GPU에서도 `--data_device cpu` 옵션으로 VRAM을 아껴 작은 장면은 학습 가능하다는 커뮤니티 보고 확인.
- OOM 발생 시 `--densify_grad_threshold` 상향, `--densification_interval` 조정, `--densify_until_iter` 축소로 완화 가능하나 **결과 품질 저하**는 공식 README도 인정하는 트레이드오프.

**종합 판단(추정 포함, 사실과 구분)**:
- 1차 우선 3편(PhysGaussian·Spring-Gaus·URDFormer)은 저자가 제공하는 **소규모 단일 물체 데모/체크포인트 추론**이 목표라 8GB로도 시도 가능할 가능성이 있음 — 단 실제로 돌려봐야 확답 가능하며 이는 추정입니다.
- 이후 연구실 자체 물체를 직접 스캔해 새로 학습시키는 단계로 가면 장면이 커져 8GB에서 OOM 가능성이 커짐.

## 5. 종합 비교

| 항목 | RTX 5090 | RTX 2080 (8GB 기준) | 논문 저자들이 실제 쓴 급 (참고) |
|---|---|---|---|
| 소프트웨어 호환성 | ❌ 재빌드 필요(1회성 작업) | ✅ 그대로 작동 | — |
| VRAM 여유 | ✅ 충분(32GB) | ❌ 부족 가능(8GB) | RTX 3090(24GB) ~ A6000(48GB) |
| 1차 우선 3편 데모 재현 | 재빌드 후 가능 | 가능성 있음(미확인) | 원 저자 기준 확실히 가능 |
| 자체 물체 신규 학습 확장 | 재빌드만 하면 여유 있음 | OOM 위험 증가 | 여유 있음 |

**결론**: 논문 저자들이 실제로 쓴 것과 가장 가까운 급은 **RTX 3090/4090(24GB, Ampere/Ada)**입니다 — 소프트웨어 호환성 문제도 없고(5090과 달리), 공식 권장 VRAM(24GB)도 충족합니다(2080과 달리). 5090·2080 둘 다 "최대 쓸 수 있는 컴퓨터" 후보로는 각각 다른 종류의 극복 가능한 리스크(전자는 1회성 빌드 작업, 후자는 장면 규모 제한)를 안고 있다는 점을 팀 내에서 인지하고 진행하면 됩니다.
